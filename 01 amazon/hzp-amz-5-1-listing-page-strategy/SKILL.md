# HZP Amazon 5-1｜页面策略

## 定位与边界

5-1 回答：“这个已经确定的产品，在 Amazon 页面上应该如何让消费者快速看懂、相信并产生购买理由？”

- 4-2 = 是否准备量产；5-1 = 页面销售战略；5-2 = Listing 文案；5-3 = 图片/视频策划；5-4 = 页面审核优化。
- 5-1 只决定讲什么、先讲什么、用什么证据、放在哪个页面载体；不直接完成最终标题、五点、描述、A+全文、图片或视频成片，不重新设计产品或重新做市场进入判断。
- 一次运行连续完成已经定义的页面策略步骤，不要求用户逐阶段确认。
- 输出以中文为主，保留 Amazon 必要英文术语和关键词，并区分事实、人工思路、分析推断与待验证。

## 产品身份和必读输入

1. 使用本次已确认的 Product Root，读取 01_产品档案.md，确认 Product Code、产品中文名称和站点。身份缺失、冲突或无法确认时停止，输出 [产品档案缺失]、[产品身份冲突] 或 [产品身份无法确认]；禁止根据 ASIN、文件名或目录名猜名称。
2. 必须读取同一 Product Root 的 03_产品页面思路.md。保留人工原意，但将其中内容标为 [人工页面思路]、[人工判断]、[页面方案意向]、[项目约束] 或 [待验证]；不能因为人工偏好就自动当作事实或页面 P0。
3. 主动读取当前产品真实状态。优先级为 4-2 量产冻结状态 > 4-1 真实样品评审 > 3-3 方案评审 > 3-2 产品方案 > 3-1 产品机会；如上游版本冲突，优先真实、更新且有证据的 4-1/4-2，并在报告记录变化。
4. 只在同一 Product Root 的 06_SKILL分析报告/ 递归查找版本化上游正式 HTML，匹配当前产品代码和目标 Skill 编号。取最大 V，同 V 取文件名 YYYYMMDD_HHMMSS 最大者；不能依赖目录顺序、文件系统时间或找到的第一个文件。
5. 排除 index.html、Draft、Preview、Test、Temp、Demo、Debug、失败、未完成、废弃、无效和临时文件。最新版有效性无法确认时输出 [上游报告有效性无法确认]，不得静默回退旧版；最新版疑似异常时仍使用最新版并标记 [建议复核上游最新版]。
6. 优先读取 3-1、3-2、3-3；按需读取 4-1、4-2 和 2-3、2-2、2-1。只记录本次实际读取的上游报告，不重新完整执行这些 Skill。

正式 HTML 必须有《输入版本追溯》，记录 Skill 编号、中文名称、实际文件名、版本号、文件名生成时间、输入类型（【核心输入】/【辅助回查】/【历史版本对照】）和本次用途。01_产品档案.md、03_产品页面思路.md、07_产品资料属于非版本化资料，单独列入资料来源。

## 事实与表达证据

统一标签：

- [已确认事实]、[实测证据]、[测试结果]、[消费者证据]、[工程确认]、[供应商确认]、[文件记录]
- [人工页面思路]、[项目主张]、[分析推断]、[待验证]、[证据不足]、[禁止表达]

页面表达强度必须匹配证据。未测试的性能、未确认的材料/认证/IP、供应商口头说法、AI 推断和设计目标不得写成已验证卖点。标准配置标记 [市场常见配置]，除非有明确优于市场的证据。Best、#1、Safest、100% Safe、Guaranteed、Unbreakable、Medical Grade、FDA Approved、Certified、Patented、Amazon’s Choice 等绝对或认证性表达没有适用证据时标记 [禁止表达] 或 [需合规/证据确认]。不得编造消费者反馈、关键词、测试、认证或专利状态。

## 固定执行流程

读取身份 → 读取 03_产品页面思路 → 读取最新有效产品状态 → 读取 3-1/3-2/3-3 → 按需回查 4-1/4-2/2-3/2-2/2-1 → 页面身份与消费者 → 页面购买逻辑 → 页面卖点优先级 → 卖点—证据矩阵 → 购买顾虑 → 第一屏 → 页面信息架构 → 页面载体映射 → 品牌与视觉方向 → 表达风险 → 人机分歧 → 反方检查 → 形成同源的 5-2 和 5-3 输入交接包 → 生成正式 HTML → 确认落盘 → 调用 0-2。

## 必须生成的页面战略内容

### 《页面核心战略》

包含目标消费者、核心场景、消费者问题、页面 P0/P1/P2、页面一句话购买理由、核心差异化、最大购买顾虑、最强信任证据、页面调性、品牌表达方向、第一屏应传递的信息和不能抢注意力的次要信息。

必须把“产品机会 P0/P1”和“页面表达 P0/P1/P2”分开：

- 页面 P0：消费者第一时间必须理解的购买理由。
- 页面 P1：强化购买理由的重要差异化或证据。
- 页面 P2：解除顾虑、补充体验或品牌强化。

### 《页面购买逻辑链》

必须写成：消费者问题 → 想获得的结果 → 产品如何解决 → 为什么更值得选 → 消费者如何感知 → 用什么证据证明 → 为什么值得购买。不能只平铺材料、厚度、配件和外观等 Feature。

### 《页面卖点优先级》

逐项记录：卖点、页面优先级、对应 3-1 P0/P1、消费者问题、消费者价值、购买理由、可感知性、当前证据、建议表达强度和备注。遵守“少而强”，不强行固定卖点数量；识别核心购买理由、支持证据、辅助功能、标准配置和不值得占重要位置的信息。

### 《卖点—证据矩阵》

记录页面卖点、对应问题、产品价值、购买理由、事实依据、来源、证据状态、是否允许强表达、是否需要弱化、是否待验证和风险。性能只有在实测/测试/正式文件支持时才能按强度表达；材料、认证和 IP 同理。

### 《购买顾虑地图》

至少检查价格、性能可信度、安装、适配、材料、尺寸、安全、复杂度和差异看不懂等顾虑，并说明是否需要页面主动处理以及可用证据。页面既要回答“为什么买”，也要回答“为什么可能不买”。

### 《第一屏策略》和《页面信息架构》

第一屏明确最重要信息、核心视觉、第一购买理由、第一证明、最大顾虑和不能抢位的次要信息。信息接收顺序按产品复杂度动态选择，通常包括：停留理由 → 信任理由 → 差异化 → 使用/安装 → 场景/人群 → 顾虑处理 → 辅助价值；不要求所有产品固定七层。发现小卖点（赠品、配件、包装）抢走核心价值时标记 [页面优先级错误]。

### 《卖点—页面载体映射表》

只为真正适合的信息推荐载体，并记录信息/卖点、页面优先级、消费者价值、证据类型、推荐载体、是否必须前置、视觉适配度、文字适配度和备注。可选载体：主图、副图、标题、五点、产品描述、A+、视频、Comparison Chart、Brand Story。

5-1 只定义主图销售任务，不制作主图；只定义标题/五点应优先承担的信息，不完成最终 Listing；关键词只用于理解消费者如何称呼产品和页面必须讲清什么，不把本 Skill 变成完整关键词研究。

### 《品牌与视觉表达方向》

结合产品证据和 03_产品页面思路定义品牌调性、页面气质、消费者心理感受、视觉关键词，以及高端/专业/家庭/安全/工程/生活方式/礼品等相关方向。没有 01、03 或上游依据时标记 [品牌定位待确认]，不得擅自发明宏大品牌故事；视觉必须服务理解、差异化和购买理由。

### 《页面表达风险与禁止项》

检查未验证性能、未确认材料/认证/IP、绝对化或医疗/安全夸张、儿童强保证、真实产品不一致、竞品攻击、品牌侵权、无依据 No.1/Best、Amazon 政策风险和旧版本卖点。任何“比竞品更好”必须写清维度和证据，不得使用无依据的 Better than competitors。

### 《页面策略分歧》和《反方检查》

若 03 人工页面思路与上游证据明显冲突，保留两方，不静默覆盖，记录人工观点、AI/证据观点、冲突点、当前证据、建议处理方式和是否影响 5-2/5-3。

反方检查至少回答：第一卖点是不是消费者最重要购买理由；小卖点是否抢位；是否把工程升级当消费者价值；标准配置是否冒充差异化；卖点消费者是否能感知；强表达是否有证据；是否只讲“我们有什么”；关键词是否压过购买逻辑；人工偏好是否与证据冲突；是否仍使用被 4-1/4-2 修改掉的旧卖点；消费者前 5 秒能否理解产品值得继续看；为什么选择当前战略。

## 5-2 与 5-3 输入交接包

正式报告必须分别生成《5-2输入交接包》和《5-3输入交接包》，二者必须来自同一份《页面核心战略》，不能出现文案讲 A、图片讲 B。

5-2 包至少含：页面策略状态、产品定义、目标消费者、场景、页面 P0/P1/P2、一句话购买理由、核心差异化、消费者价值、最大顾虑、信任证据、可用事实/性能/材料、关键词与意图、品牌方向、标题与五点职责、描述/A+职责、必须避免的表达、待验证表达和证据状态。它是文案战略，不得直接代写完整标题、五点或 A+。

5-3 包至少含：页面策略状态、产品定义、目标消费者、场景、页面 P0/P1/P2、第一屏策略、核心视觉信息、差异化、消费者价值/购买理由、需要视觉/结构/场景/使用/对比证明的信息、品牌与视觉方向、必须保留的产品结构、不能夸大的性能、待验证视觉主张和禁止视觉表达。它是图片视频策划输入，不直接制作图片或视频。

## 最终状态

只允许：

1. 【页面策略已形成｜进入5-2/5-3】
2. 【页面策略基本形成｜存在待确认信息】
3. 【关键产品事实不足｜暂无法形成可靠页面策略】
4. 【上游产品定义发生冲突｜需返回确认】

若产品定义、消费者、P0/P1、核心购买理由和差异化均清楚且核心证据足够，可用状态 1；少量材料、测试、规格、品牌或表达证据待确认但不阻碍战略时用状态 2；关键产品本身或差异化不明确时用状态 3；身份或上游定义冲突时用状态 4。不得使用 GO、NO-GO 或 CONDITIONAL GO 作为 5-1 的最终状态。

详细字段见 references/page-strategy-framework.md 和 references/handoff-schema.md；报告结构见 templates/report-outline.md。
