# HZP Amazon 5-2｜Listing文案

## 定位与边界

5-2 把 5-1 已确定的页面销售战略写成面向 Amazon US 消费者的正式英文 Listing 文案，并把证据边界交给 5-3 和 5-4。它负责关键词理解与布局、Title、Bullet Points、Product Description、A+ 文字基础、Claim 审核和 SEO/可读性检查。

- 5-1 决定卖什么、先讲什么和页面购买逻辑；5-2 负责把它写出来；5-3 负责图片/视频策划；5-4 负责页面审核优化。
- 不重新做市场分析、产品开发或页面战略；不制作图片、视频成片或完整 A+ 视觉模块；不得擅自改变 5-1 的 P0/P1/P2 和核心卖点优先级。
- 正式 Amazon 文案以自然、清晰的美国英语为准；报告用中文解释，英文文案本体不混入中文。
- 一次运行连续完成所有已定义步骤，不要求用户逐阶段确认。

## 产品身份和输入

1. 使用本次确认的 Products Root 与 Product Root。读取同一 Product Root 的 `01_产品档案.md`，确认 Product Code、产品中文名称、站点和产品身份。身份缺失或冲突时停止，输出 `[产品档案缺失]`、`[产品身份冲突]` 或 `[产品身份无法确认]`；禁止根据 ASIN、文件名或 Niche 猜产品名称。
2. 必须读取同一 Product Root 的 `03_产品页面思路.md`。保留人工原意，并标注 `[人工页面思路]`、`[人工判断]`、`[页面方案意向]`、`[项目约束]` 或 `[待验证]`；人工偏好不能自动升级为事实或页面 P0。
3. 在 `[Product Root]/06_SKILL分析报告/` 中按“当前 Product Code + Skill 编号”定位最新有效的 5-1 正式 HTML：最大 V 优先，同 V 取文件名 `YYYYMMDD_HHMMSS` 最新者。排除 `index.html`、Draft、Preview、Test、Temp、Demo、Debug、失败、未完成、废弃、无效和临时文件；不得依赖目录顺序或文件系统时间。最新版异常时使用最新版并标记 `[建议复核上游最新版]`，不得静默回退。
4. 读取 5-1 报告中的《5-2输入交接包》，作为核心输入；只有为核实具体 Claim 时，才按需回查 4-2、4-1、3-3、3-2、3-1、2-3、2-2、2-1 的最新有效报告，不重新执行这些 Skill。若 4-1/4-2 的真实产品状态与 5-1 冲突，优先当前真实状态；冲突影响页面战略时输出 `[上游页面策略冲突｜需返回5-1]`，不在 5-2 中偷偷改战略。
5. 主动检查 `[Product Root]/05_分析源数据/03_关键词数据/`，读取实际字段、数据日期、数据语义和来源。可识别 Cerebro、Magnet、ABA、Search Query Performance、Brand Analytics、Search Terms、Keyword Tracker、广告搜索词等，但文件名只是线索，内容才是证据。
6. 可按需读取真实评论和产品资料用于 Claim/消费者表达核实；真实评价必须保留来源和原意，不编造或拼接 Quote。

正式 HTML 必须包含《输入版本追溯》，只记录本次实际读取的版本化正式报告，并标明 5-1 为 `[核心输入]`、其他回查为 `[辅助回查]`；`01_产品档案.md`、`03_产品页面思路.md` 和原始关键词文件单列为非版本化资料。

## 证据、关键词与 Claim 规则

统一区分 `[已确认事实]`、`[实测数据]`、`[测试结果]`、`[消费者证据]`、`[工程确认]`、`[供应商确认]`、`[文件记录]`、`[项目主张]`、`[分析推断]`、`[待验证]`、`[证据不足]`。表达强度不得超过证据强度；供应商说法不能写成实测，AI 推断不能写成消费者事实。

关键词先按消费者搜索意图理解，再决定位置。至少考虑 `[核心产品词]`、`[核心购买意图词]`、`[核心场景词]`、`[属性词]`、`[问题词]`、`[长尾词]`、`[相关但低优先级]`、`[不建议使用]`。关键词数据不足时不得编造搜索量、排名、点击、购买、Organic Rank、CPC、转化率或“高流量/高转化/低竞争”等结论；可形成 `[关键词证据不足｜可先形成转化版文案]`。

重要 Claim 必须进入《Claim—Evidence检查表》，状态只能使用：

- `[可直接表达]`
- `[建议弱化表达]`
- `[需补证据]`
- `[禁止表达]`

重点检查承重、材料等级、防水/防火、医疗/健康、儿童安全、认证、专利、绝对安全、比较广告和其他 Amazon 政策风险。Best、#1、Safest、100% Safe、Guaranteed、Unbreakable、Certified、FDA Approved、Patented 等没有充分依据时禁止表达。关键词中出现无授权竞品品牌，标记 `[不建议用于正式Listing]`，不得硬塞前台文案。

## 固定执行流程

读取身份 → 读取 `03_产品页面思路.md` → 选择最新有效 5-1 → 优先读取《5-2输入交接包》 → 主动检查关键词资料 → 按需核实产品/消费者证据 → 继承页面战略 → 关键词分类与使用地图 → Title 方案与推荐 → Bullet Points 正式稿 → Product Description 正式稿 → A+ 文字建议 → Claim—Evidence 审核 → SEO 与可读性检查 → 反方检查 → 形成 5-3 文案协同包 → 形成 5-4 输入交接包 → 生成正式 HTML → 确认文件存在和命名正确 → 调用 0-2。

## 必须生成的内容

### 《Listing文案战略摘要》

至少包含目标消费者、核心场景、页面 P0/P1/P2、核心产品词、主搜索意图、一句话购买理由、核心差异化、文案调性、最重要 Claim、最大购买顾虑、禁止 Claim 和最大待确认信息。不能因为单个关键词搜索量高就改变 5-1 页面战略。

### 《关键词使用地图》

每个实际采用或排除的关键词记录：Keyword、中文含义、搜索意图、数据来源、真实指标（有则列出）、产品相关性、角色、推荐位置、是否需要原词出现、是否可自然变体和风险/备注。禁止机械密度、重复堆词和不自然语序；搜索覆盖必须服从理解、信任和转化。

### 《Title方案与最终推荐》

提供少量真正有差异的方案（通常 2–3 个，明显最佳时可少于 2 个），例如转化优先、SEO/转化平衡、移动端精简，并明确《推荐正式Title》及理由。Title 必须让美国消费者看懂产品是什么、主要购买意图和决定性差异化，不能成为关键词仓库或无依据 Claim。

### 《Bullet Points正式稿》

按 5-1 页面 P0/P1/P2 排序，重要价值尽量前置，兼顾移动端只读前半句的场景。每条优先采用：消费者问题 → 产品解决方式 → 消费者价值 → 支持证据 → 使用/购买结果；不能只平铺 Feature。数量按实际 Amazon 类目和页面需要处理，不为固定五点制造空洞内容。

### 《Product Description正式稿》

英文 Description 不机械复制 Bullet，承担完整价值、使用逻辑、场景、适配/兼容、安装/使用、注意事项、顾虑解除和品牌补充；仅写已有证据支持的事实。

### 《A+文字内容建议》

提供核心品牌/产品价值、差异化、结构/材料解释、场景、使用方法、兼容性、顾虑解除、对比文字和 FAQ 方向中实际需要的部分。只做文字战略与基础文案，不设计完整 A+ 视觉模块。

### 《Claim—Evidence检查表》

逐项记录 Claim、使用位置、消费者价值、证据来源、证据类型、当前状态、建议表达方式、风险和最终处理。证据不足时给出中性替代表达或列为待验证，不能为了转化硬写。

### 《SEO与可读性检查》

检查核心产品词和搜索意图覆盖、关键词堆砌/重复、自然美国英语、Title 复杂度、Bullet 长度、重要信息前置、Bullet 之间重复、Description 与 Bullet 重复、Feature 堆砌、AI 广告腔、证据不足 Claim 和绝对化表达。

### 《反方检查》

至少回答：Title 第一眼是否看懂产品；是否成关键词仓库；最重要购买理由是否前置；Bullet 是否讲消费者价值；小卖点是否抢位；关键词是否与真实产品匹配；Claim 是否超过证据；是否把供应商说法写成测试事实；是否把 AI 推断写成消费者事实；是否不当使用竞品品牌；是否像自然 Amazon US 页面；移动端只看前半段时核心价值是否成立；是否偷偷改变 5-1 战略；Title + 前两个 Bullet 是否已说明主要购买理由；为什么推荐当前版本。

### 《5-3文案协同包》

向图片/视频策划传递与 5-1 同源的推荐 Title、页面 P0/P1/P2、核心购买理由、核心差异化、适合上图的短卖点、可视觉化 Claim、可展示数字、材料/结构、需要证明的信息、安装/使用重点、消费者顾虑、视频表达信息、禁止视觉夸张内容、待验证 Claim 和证据状态。短文案只作视觉素材，不替代 5-3 设计。

### 《5-4输入交接包》

至少传递 5-2 最终状态、推荐 Title、正式 Bullet、Product Description、A+ 文字建议、核心关键词地图、页面 P0/P1/P2、核心 Claim 及证据状态、待验证 Claim、禁止表达、SEO/可读性检查结果和 5-4 应重点审核的问题。

上述两个交接包必须来自同一份页面核心战略，不能文案和视觉分别采用不同的卖点。

## 最终状态

只允许：

- `【Listing文案已形成｜可进入5-3/5-4】`
- `【Listing文案基本形成｜存在待确认Claim】`
- `【关键词证据不足｜可先形成转化版文案】`
- `【关键产品事实不足｜暂无法形成可靠文案】`
- `【上游页面策略冲突｜需返回5-1】`

待确认 Claim 不自动阻止其他可靠文案；如果连产品是什么、核心规格、材料和核心差异化都无法可靠确认，才使用关键事实不足，不得硬写。

## 正式 HTML 与 0-2 联动

报告只写入当前 Product Root 的 `06_SKILL分析报告/`，不覆盖历史文件：

`5-2_[产品编号]_Listing文案_V[最大版本号+1]_[YYYYMMDD]_[HHMMSS].html`

正式报告固定包含：

1. 产品身份与《Listing文案结论》
2. 《输入版本追溯》
3. 《Listing文案战略摘要》
4. 《关键词使用地图》
5. 《Title方案与最终推荐》
6. 《Bullet Points正式稿》
7. 《Product Description正式稿》
8. 《A+文字内容建议》
9. 《Claim—Evidence检查表》
10. 《SEO与可读性检查》
11. 《反方检查》
12. 《5-3文案协同包》
13. 《5-4输入交接包》
14. 数据与证据局限
15. 《名词术语解释》

首页优先显示产品代码+中文名称、5-1 来源版本、一句话文案策略、最终状态、推荐 Title、页面 P0、核心产品词、核心购买理由、最重要 Claim、最大 Claim 风险、最大待确认项和下一步 5-3/5-4。报告使用 UTF-8、响应式布局和清晰证据标签；不为“视觉丰富”强行生成图表，不使用雷达图、综合评分、AI 信心分、3D 图表或花哨动画。

只有正式 HTML 成功写入、确认文件存在且文件名正确后，才调用 `hzp-amz-0-2-report-index`，并原样传递本次已确认的 Product Code、Products Root、Product Root。5-2 不得扫描、生成、排序、维护或备用更新 `index.html`。报告失败不调用 0-2；报告成功但 0-2 失败时保留正式报告，并明确“正式报告：生成成功；报告索引：更新失败；原因：[实际原因]”。

## 禁止事项

禁止脱离 5-1 重新定义页面战略；为了高搜索量改变产品定位；编造关键词、搜索量、排名、点击、购买、CPC、转化率、规格、材料、测试、认证、专利或消费者评价；把 AI 总结冒充 Quote；把供应商说法冒充实测；把待验证 Claim 写成事实；滥用绝对化表达或无授权竞品品牌；关键词堆砌；Feature 堆砌；输出大量候选让团队重新做选择题；修改 `03_产品页面思路.md`、原始关键词数据、历史 HTML 或 `index.html`；复制 0-2 的索引逻辑。

详细字段、Claim 审核和 HTML 章节见 `references/keyword-and-claim-policy.md`、`references/handoff-schema.md` 和 `templates/report-outline.md`。
