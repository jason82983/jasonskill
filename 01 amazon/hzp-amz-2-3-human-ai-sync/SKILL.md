# HZP Amazon 2-3｜人工判断与AI同步

## 任务边界

本 Skill 处理同一产品的人工输入与前序 AI/数据证据之间的正式同步。它负责记录、分类、对照、识别冲突、保留来源并整理给 `hzp-amz-3-1-product-development` 的输入；不重新全面执行 2-1 或 2-2，不修改人工原始文件，不输出市场 `GO / CONDITIONAL GO / NO-GO`，不完成最终产品定义或详细工程设计。

## 运行前提与身份

1. 从 `[Product Root]/01_产品档案.md` 读取产品编号和产品中文名称。标题和身份卡必须显示“人工判断与AI同步｜产品编号 产品中文名称”；不得从 ASIN、Niche、文件名或目录名猜名称。
2. 产品档案缺失时输出 `[产品档案缺失]` 并停止正式同步。产品编号、名称或 Product Root 身份冲突时输出 `[产品身份冲突]`，列出冲突字段并停止；不得自行择一。
3. 主要人工输入是 `[Product Root]/02_产品开发思路.md`。文件不存在、为空或没有可识别的人工判断、约束、假设、方案意向时，输出 `[缺少人工输入]` 并停止正式同步；不得由 AI 反向编造“用户/QMT/团队认为”。
4. 在 `[Product Root]/06_SKILL分析报告/` 中识别同一产品的最新有效 2-1 与 2-2 正式报告。按标准文件名的版本号和时间排序；历史报告只能作为回查证据，不能静默覆盖。2-1 或 2-2 单独缺失时继续并标记 `[产品分析缺失]` 或 `[细分市场分析缺失]`；两者均缺失时原则上停止。
5. 只有发现冲突、需核实前序引用或关键证据不足时，才回查 `[Product Root]/05_分析源数据/`；不得借 2-3 重新跑完整市场研究。

## 人工输入与证据规则

只把 `02_产品开发思路.md` 明确写出的内容视为人工输入，并保留原始表述、来源文件、来源人（无法确认写 `[来源未明确]`）、验证状态。按需要使用以下七类：

- `[人工事实]`：有明确来源且可验证的事实。
- `[专家判断]`：用户、QMT、开发、供应商等基于经验的判断。
- `[产品假设]`：关于结构、材料、规格、功能或组合可能改善问题的假设。
- `[商业假设]`：关于售价、目标人群、溢价、转化或市场接受度的假设。
- `[方案意向]`：团队倾向采用的方向，不等于最终产品定义。
- `[项目约束]`：成本、售价、周期、尺寸、重量、包装、材料、供应链或工艺边界。
- `[待验证]`：来源、证据或确认不足的内容。

“我感觉不错”“应该能卖”等弱表述标记 `[弱人工判断]` 或 `[待验证]`。若不影响开发决策，可留在正文但过滤出 3-1 核心交接包。

对照时保留统一证据状态：`[数据支持]`、`[主题数据支持]`、`[多源交叉验证]`、`[分析推断]`、`[待验证]`、`[证据不足]`、`[数据冲突]`、`[待供应链验证]`、`[IP风险待验证]`、`[合规风险待验证]`。不得把前序 `[分析推断]`升级为事实。

## 人工 × AI 对照

每条会影响开发的重要人工观点，都要尝试与真正相关的 2-1/2-2 证据对照，先确认判断对象、指标口径和时间范围相同，再分类为且仅为以下六种关系：

- `【一致】`：方向明显一致。
- `【部分一致】`：方向一致但程度、范围、原因或条件不同。
- `【人工补充AI】`：人工提供供应链、工艺、成本、资源或其他 AI 无法直接获得的信息。
- `【AI补充人工】`：AI 用数据补充人工未展开的需求、竞争、搜索或市场结构。
- `【存在冲突】`：同一判断对象、可比较口径和相近时间范围下，证据方向明显相反。
- `【无法验证】`：现有资料不足；“AI没有找到证据”不等于人工错误。

标记 `【存在冲突】` 前必须先排除假冲突。例如“结构好做”与“市场进入难度高”可能分别谈工程难度和市场难度，不能直接判为冲突。真实冲突必须同时展示人工判断、AI/数据证据、冲突对象、口径原因、相对证据强度、未确定事项和验证办法；不得自动采用任一方。

重要同步事项使用 `[强证据]`、`[中等证据]`、`[弱证据]`、`[无直接证据]`。不要生成 87 分、置信度 83% 等伪精确总分。

## 正式报告

输出目录固定为 `[Product Root]/06_SKILL分析报告/`，只新增、不覆盖历史文件：

`2-3_[产品编号]_人工判断与AI同步_V[最大版本号+1]_[YYYYMMDD]_[HHMMSS].html`

HTML 使用中文优先，图表只在有实际数据意义时使用，主要用表格、矩阵、标签和卡片。必须包含以下固定章节：

1. 标题与产品身份
2. 一句话同步结论
3. 人工输入概览
4. 人工判断分类概览
5. 《人机一致项》
6. 《人工判断 × AI证据同步矩阵》
7. 《重大人机冲突》；无重大冲突时明确写 `[当前未发现证据充分的重大人机冲突]`
8. 《人工补充信息》
9. 《人工假设池》
10. 《关键待验证事项》
11. 《3-1输入交接包》
12. 数据与证据局限
13. 名词术语解释

首页顺序应让管理者先看到产品身份、人工核心判断、AI 核心判断、总体同步关系、最重要一致项、最大冲突、待验证事项，以及“是否具备进入 3-1 的信息基础”。最后一项只能使用：`【同步信息充分，可进入3-1】`、`【同步信息基本充分，但存在待验证事项】`、`【人工输入不足】`、`【AI证据不足】`、`【关键冲突未澄清】`；这不是市场进入决策。

《3-1输入交接包》是 HTML 内的正式章节，不另造重复报告。仅纳入会影响“开发什么、为什么开发、有哪些约束、有哪些风险”的六类信息：已确认项目约束、值得继承的专家判断、核心产品假设、核心商业假设、重大人机冲突、进入 3-1 后的关键验证事项。每项保留人工来源、AI 对应证据、同步关系、证据状态、影响原因和验证建议；不得把临时想法直接升级为产品定义。

## 完成后的 0-2 联动

正式 HTML 成功写入并确认文件存在后，调用 `hzp-amz-0-2-report-index`，原样传递本次已确认的 Product Code、Products Root 和 Product Root。2-3 不扫描、生成、排序、维护或备用更新 `index.html`。若 0-2 失败，保留正式报告并明确返回“正式报告：生成成功；报告索引：更新失败；原因：[实际原因]”。若正式报告生成失败，不调用 0-2。
