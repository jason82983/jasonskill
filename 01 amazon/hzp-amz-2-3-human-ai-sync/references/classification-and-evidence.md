# 分类与证据强度

## 人工输入分类

| 标签 | 使用条件 | 不得升级为 |
|---|---|---|
| `[人工事实]` | 有明确来源且可验证 | 最终产品定义 |
| `[专家判断]` | 用户、QMT、开发、供应商等经验判断 | 数据事实 |
| `[产品假设]` | 结构、材料、规格、功能可能改善问题 | 已验证需求 |
| `[商业假设]` | 售价、人群、溢价、转化、接受度判断 | 市场事实 |
| `[方案意向]` | 团队当前倾向方向 | 最终方案 |
| `[项目约束]` | 成本、周期、尺寸、重量、包装、供应链等边界 | 可忽略条件 |
| `[待验证]` | 来源或证据不足 | 已确认结论 |
| `[弱人工判断]` | “感觉不错”“应该能卖”等弱表述 | 人工事实 |

## 关系标签

只使用 `【一致】`、`【部分一致】`、`【人工补充AI】`、`【AI补充人工】`、`【存在冲突】`、`【无法验证】`。冲突需要同一对象、可比较口径和相近时间范围；否则优先使用部分一致、补充或无法验证。

## 证据强度

- `[强证据]`：多源交叉、跨 ASIN 一致、真实市场行为、明确供应商确认或真实测试结果。
- `[中等证据]`：单一可靠来源或有明确依据但未多源验证。
- `[弱证据]`：少量 Review、单 ASIN 现象、单人经验或未验证推断。
- `[无直接证据]`：当前资料无法支持或反驳。

证据状态与强度分开填写；例如 `[分析推断] + [中等证据]`，不要合并成伪精确分数。
