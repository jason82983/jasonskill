# 路由、提醒去重与 0-2 边界

## 路由

0-3 只识别时间风险并给出 `[建议调用Skill]`：

| 信号 | 路由 |
|---|---|
| 产品/市场分析需要启动 | 2-1 / 2-2 |
| 产品机会或差异化开发 | 3-1 / 3-2 |
| 样品评审或量产前检查 | 4-1 / 4-2 |
| 页面战略、文案、视觉、审核 | 5-1 / 5-2 / 5-3 / 5-4 |
| Launch准备 | 6-1 |
| 广告异常 | 6-2 |
| 店铺/经营异常 | 6-3 |
| 补货预测 | 7-1 |
| 库存风险 | 7-2 |

不要复制被路由 Skill 的分析算法、阈值或写操作。

## 提醒去重

建议在 `Amazon经营预报` 下保存轻量状态，例如 `reminder-state.json`。以 `product_code + event_id + action_type` 为键，记录上次提醒日期、阶段、风险、阈值和动作。仅当阶段、风险、阈值、动作、官方日期或重大经营异常变化时再次提升优先级；否则可在日报中折叠或不重复展示。状态文件不是正式报告，也不进入 0-2 索引。

## 0-2兼容

正式报告根目录仍由 0-2 维护。高频预报放在 `[Product Root]\06_SKILL分析报告\Amazon经营预报\`，默认使用 Markdown/JSON，不要自行生成 `index.html`，不要扫描历史正式报告，也不要实现排序或索引 CSS/JS。只有用户明确要求正式 HTML 时，才写入 `06_SKILL分析报告\` 根目录并调用 0-2。当前 0-2 已排除 `广告表现汇报优化日志/`；若其扫描规则未来变化，先做兼容性审计再改动 0-3。
