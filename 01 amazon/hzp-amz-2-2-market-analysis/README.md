# HZP Amazon 2-2｜细分市场分析

## 30 秒运行

```text
使用 2-2 Skill
产品：P001
Products Root：E:\【产品总目录】
```

2-2 会自动在该产品的 Product Root 中读取 `01_产品档案.md`，扫描 `05_分析源数据/`，按文件实际字段和数据日期识别可用证据，并连续执行当前版本已经定义的市场分析能力。

正式报告顶部会显示“产品：产品代码 + 产品中文名称”；两项身份均来自当前 Product Root 的 `01_产品档案.md`。名称缺失会显示 `[产品名称缺失]`，身份冲突会停止生成报告并说明冲突字段。

正常运行不会要求你逐阶段回复“通过”或重新指定某个 CSV、H10、Niche、评论文件。只有产品身份、关键 ASIN 或核心市场证据无法安全确认时，才会暂停并说明需要补什么。

当前版本会正式执行阶段 1｜市场定义与范围确认、阶段 2｜真实市场需求验证、阶段 3｜市场商业价值判断、阶段 4｜竞争强度与进入难度判断、阶段 5｜消费者未满足需求分析、阶段 6｜产品切入机会验证、阶段 7｜市场进入决策，并选择仍然有效、有数据支持的旧组件作为辅助分析。七阶段均已正式设计。阶段 2 验证真实需求，阶段 3 评估销售与利润空间，阶段 4 评估商品/品牌集中度、头部壁垒、新品进入门槛和付费流量压力，阶段 5 交叉验证消费者购买目的、不满意问题、市场共性、重要程度、现有解决程度和商业信号，阶段 6 把阶段 5 的 P0/P1 未满足需求转化为产品化、可超越、可感知、可购买且基本可实现的切入机会，阶段 7 综合前六阶段执行硬否决、正反方检查并形成 GO / CONDITIONAL GO / NO-GO / INSUFFICIENT EVIDENCE 决策；缺失数据会标记并说明影响，不用经验值填空。

报告输出到：

```text
[Product Root]/06_SKILL分析报告/2-2_细分市场分析/
```

正式 HTML 成功生成后，2-2 会自动调用 0-2 更新同一产品的 `index.html`。2-2 不自行生成或维护索引。

研究状态保存在同一报告目录的 `2-2_[产品编号]_RESEARCH_STATE.md`。原始资料保持只读。


上游报告规则：如本次读取其他 Skill 正式报告，只在当前产品的 06_SKILL分析报告/ 中按产品编号、Skill 编号、最大 V 版本和同版本最大文件名时间戳选择最新有效正式版本；实际使用的文件会写入 HTML《输入版本追溯》。
