# 2-2 术语与高级报告展示规范

本规范只约束 HTML 报告的视觉层和术语解释层，不改变数据读取、计算公式、证据等级、市场判断、GO/CONDITIONAL GO/NO-GO 或目录结构。

## 高级报告视觉原则

完整 2-2 HTML 统一采用专业、克制、清晰的管理层报告风格。每个正式分析模块按以下顺序组织：

`分析标题 → 一句话核心结论 → KPI 卡片 → 图表 → 精确数据表 → 简短解释 → 相关术语`

统一字体层级、卡片圆角、轻阴影、边框、模块间距、图表标题、数字格式、强调色、Tooltip 和表格样式。使用中性背景、有限低饱和色和清晰留白；不使用大面积高饱和色、过多渐变、3D、炫技动画或每个模块各自一套设计。目标是高级商业分析报告，而不是数据后台界面。

## 模块术语入口

每个正式分析模块结束后必须增加一行辅助信息：

`相关术语：术语 A · 术语 B · 术语 C`

- 只列出该模块实际出现且值得解释的术语；同一术语可被多个模块链接，但整份报告只建立一个解释卡片；
- 入口字号建议 12–13px，使用低饱和辅助文字，不放在标题旁、KPI 卡中央或核心结论上方；
- 每个术语文字都是 `<a>` 链接，指向底部唯一的 `id`；使用轻微 Hover 反馈，不做成大按钮；
- 入口不占用过多纵向空间，不影响正文阅读。

推荐模块映射：

| 模块 | 相关术语示例 |
|---|---|
| 1 市场需求竞争比 | 自然排名、搜索量、平均竞品数量、市场需求竞争比 |
| 2 市场搜索转化效率 | 细分市场、点击份额、市场搜索点击率、搜索转化率 |
| 阶段 4 竞争强度与进入难度 | 商品竞争集中度、品牌竞争集中度、头部产品壁垒、新品进入难度、建议竞价、实际 CPC、ACoS |
| 竞争结构 | 前5商品点击占比、前20商品点击占比、品牌点击份额 |
| 消费者需求地图 | 正面反馈、负面反馈、退货洞察 |
| 产品切入机会池 / 产品切入机会地图 | 产品化可行性、可超越程度、消费者可感知性、购买理由、实现难度 |
| 市场进入决策 | GO、CONDITIONAL GO、NO-GO、INSUFFICIENT EVIDENCE、硬否决、最终裁决逻辑 |
| 消费者未满足需求 | 现有产品未充分解决、且影响购买或使用的消费者需求缺口 |
| 市场共性问题 | 在多个相关 ASIN 或市场层级重复出现的问题，不能由单个 ASIN 单独证明 |
| P0 / P1 / P2 | 按核心影响、体验影响和轻微偏好划分的问题优先级 |
| 主题数据支持 | 只有聚合主题统计、没有可引用原始评论时使用的证据状态 |
| 多源交叉验证 | 评论、主题、退货或搜索行为共同指向同一问题时的证据状态 |
| 产品切入机会 | 将阶段 5 的未满足需求转化为可产品化、可感知且有商业意义的开发方向 |
| 消费者可感知性 | 消费者在购买前能否通过 Amazon 页面或场景快速理解差异 |
| 产品化可行性 | 消费者问题能否通过产品、页面、包装或服务等明确手段改善 |
| 购买理由强度 | 差异是否足以成为消费者选择该产品的理由 |
| 待供应链验证 | 供应商、工艺、成本或量产条件尚未确认的状态 |
| IP风险待验证 | 专利、商标或其他知识产权风险尚未完成核验的状态 |
| 合规风险待验证 | 安全、法规或平台合规要求尚未完成核验的状态 |
| 硬否决 | 可靠证据确认的致命问题，不能被其他指标平均掉 |
| GO前必须验证的条件 | CONDITIONAL GO 在进入量产或大规模投入前必须关闭的可执行验证项 |
| 关键缺失证据 | 导致无法区分 GO、CONDITIONAL GO 和 NO-GO 的关键缺口 |

其他模块按实际可见术语自动收集，不机械塞入整个术语库。

## 页面底部术语区

在“证据与局限”之后、报告最底部增加独立模块：

`# 名词术语解释`

只解释本次报告实际出现的术语；以下核心术语在出现时必须解释：ASIN、对标产品、榜1/头部产品、细分市场、自然排名、搜索量、竞品数量、市场需求竞争比、商品竞争集中度、品牌竞争集中度、头部产品壁垒、新品进入难度、点击份额、市场搜索点击率、搜索转化率、商品点击份额、品牌点击份额、前5/前20商品点击占比、建议竞价、实际 CPC、ACoS、BSR、Cerebro、Amazon Opportunity Explorer、GO、CONDITIONAL GO、NO-GO、P0/P1/P2 以及 `[数据支持]`、`[分析推断]`、`[待验证]`、`[推算指标]` 等状态标签。

每个术语只建立一个唯一 HTML anchor，例如：

- `term-market-demand-competition`
- `term-organic-rank`
- `term-search-volume`
- `term-market-search-click-rate`
- `term-search-conversion-rate`

每张解释卡至少包含：

1. **术语名称**（优先中文，必要英文放括号）；
2. **指标类别**：`Amazon官方`、`H10` 或 `HZP推算`；
3. **简单定义**；
4. **数据来源/计算方式**（适用时）；
5. **意义**；
6. **在 2-2 中的作用**；
7. **使用限制/注意事项**（必要时）。

推算或自定义指标必须明确显示 `[推算指标]`，写出公式，并说明不是 Amazon 后台直接提供的官方字段。例如市场搜索点击率必须说明：`细分市场 360 天总点击量 ÷ 细分市场 360 天搜索量`，不能称为 Amazon 官方 CTR。

术语标题和定义中文优先，例如：`自然排名（Organic Rank）`、`搜索量（Search Volume）`、`竞品数量（Competing Products）`、`Amazon Opportunity Explorer（Amazon 商机探测）`。英文关键词和必要官方字段仍按中文显示规则保留。

## 跳转与布局

- HTML 使用 `scroll-behavior: smooth`；术语标题使用 `scroll-margin-top`，避免被固定导航遮挡；
- 每张术语卡底部可放置小号 `↑ 返回相关分析` 链接；多个模块共用术语时可返回首次引用位置或省略；
- 桌面端术语卡使用两列，较窄屏幕自动变为一列；卡片高度按内容自然变化，不强制等高；
- 术语解释区使用与正文相同的字体、圆角、边框和轻阴影，但视觉权重低于分析结论。

## 自动收集与去重

生成正式报告时，从实际渲染的标题、卡片、图表、表格、注释和结论中收集术语，按规范化名称去重后生成底部卡片。模块入口和底部卡片必须使用同一术语 ID；不得因入口重复而创建多个解释。术语区不能凭空增加原始数据或改变指标含义。
