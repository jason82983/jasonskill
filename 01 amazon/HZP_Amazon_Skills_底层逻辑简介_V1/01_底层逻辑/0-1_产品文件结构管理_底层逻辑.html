0-1｜产品文件结构管理

为什么这样设计

所属阶段：0｜基础
机器名：hzp-amz-0-1-product-file-structure
文件类型：底层逻辑说明
版本：V1 手册
本页用于长期回查“为什么这样设计”。正文依据当前已锁定业务设计生成；不作为真实产品分析报告。

定位与边界

只负责建立、检查、整理、迁移产品文件结构；不产生商业结论。

0-1 是文件结构层。它不做选品、分析、开发、页面、广告或库存判断；只保证后续 Skill 有稳定、可追踪的资料位置。

产品资料 → 0-1结构化 → 稳定Product Root → 后续全部Skill

核心输入

  • 产品编号
  • 中文产品名
  • Products Root / Product Root
  • CREATE / CHECK / ORGANIZE / MIGRATE 模式
  • 现有文件与目录

第一原则

  • 根目录格式：[产品编号] [中文产品名]
  • 原始数据与分析报告严格分开
  • 05_分析源数据只放输入，06_SKILL分析报告只放正式输出
  • 不修改原始数据内容
  • 不猜商业事实
  • 公共资料与产品私有资料分层

核心输出

  • 规范化产品目录
  • 缺失/异常目录检查结果
  • 整理或迁移计划
  • 明确不确定项

允许的状态 / 关键状态

  • 【结构正常】
  • 【存在结构问题】
  • 【需要整理】
  • 【需要迁移】
  • 【身份信息冲突｜停止】

典型错误与反方检查

  • 把整理文件当成分析产品
  • 修改原始数据内容
  • 把报告放进05
  • 把原始CSV放进06
  • 身份冲突时继续执行
反方检查：正式结论前必须主动问：如果当前判断是错的，最可能错在哪里？有没有把“没有证据”误写成“没有问题”？有没有把单一信号误当成最终结论？
