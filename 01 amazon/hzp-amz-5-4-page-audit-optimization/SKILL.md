# HZP Amazon 5-4｜页面审核优化

## 定位与边界

5-4 把 5-1 页面策略、5-2 Listing 文案、5-3 图片视频策划放进同一条消费者购买路径，判断页面能否让消费者快速看懂、相信并理解购买理由，并给出有业务影响的修改清单。

- 5-1 负责页面销售战略；5-2 负责 Listing 文案；5-3 负责图片/A+/视频视觉策划；5-4 负责整体审核和优化分流。
- 不重新开发产品、做市场分析、从零制定页面战略、从零重写 Listing、从零设计全部图片，或替代 5-2/5-3 完成制作。
- 一次运行连续完成已定义步骤，不要求用户逐阶段确认。

## 产品身份与输入

1. 使用本次确认的 Products Root、Product Root，读取 `01_产品档案.md` 和 `03_产品页面思路.md`。身份缺失或冲突时停止，输出 `[产品档案缺失]`、`[产品身份冲突]` 或 `[产品身份无法确认]`；禁止根据 ASIN、文件名或页面猜产品中文名称。
2. 从同一 Product Root 的 `06_SKILL分析报告/` 定位当前产品最新有效 5-1、5-2、5-3 正式 HTML：按 Product Code + Skill 编号匹配，最大 V 优先，同 V 按文件名 `YYYYMMDD_HHMMSS` 最新。排除 index、失败、草稿、测试、Preview、Temp、Demo、Debug、deprecated、invalid、incomplete 和非正式输出；不得随机取旧版或按文件系统顺序取第一份。
3. 优先读取 5-2《5-4输入交接包》和 5-3《5-4输入交接包》，同时读取 5-1 页面核心战略。按需回查 4-2、4-1、3-3、3-2、3-1、2-2、2-1，仅核对具体事实/Claim/消费者证据，不重新完整运行上游 Skill。
4. 主动检查 `[Product Root]/07_产品资料/`：最终主图、副图、A+ 成图、视频、Listing 截图、实际 Title/Bullet/Description、页面导出和版本记录。若真实页面成品存在，必须优先审核消费者实际看到的内容；若只有计划稿，明确标记 `【策划阶段页面审核】`，不得伪称 `【真实页面成品审核】`。
5. 真实页面与 5-2/5-3 规划不一致时，先审核真实页面并指出偏离；真实产品状态优先于旧计划。

正式 HTML 生成《输入版本追溯》，只记录本次实际读取的正式报告；5-1、5-2、5-3 标记 `[核心输入]`，实际回查的 4/3/2 阶段标记 `[辅助回查]`，07 页面成品和素材单独列为非版本化资料。

## 固定执行流程

读取身份 → 选择最新 5-1/5-2/5-3 → 读取两个 5-4 交接包 → 检查 07 真实页面成品 → 确定策划审核或成品审核 → 按需核实上游 → 页面战略一致性 → 前 5 秒 → 文案—视觉一致性 → 购买路径完整性 → Claim 最终审核 → SEO/可读性 → 页面真实性/合规 → 页面优化优先级 → 最终修改清单 → 反方检查 → 在条件满足时形成 6-1 输入交接包 → 生成正式 HTML → 确认落盘 → 调用 0-2。

## 必须生成的审核内容

### 《页面战略一致性检查》

沿着 `5-1 P0/P1/P2 → 5-2 文案 → 5-3 视觉 → 真实页面 → 消费者实际接收` 检查核心消费者问题、购买理由和差异化是否仍被正确表达。若 P2（赠品、包装、颜色等）抢过 P0，标记 `【页面核心战略偏离】`；不能因为视觉漂亮就判战略正确。

### 《前5秒审核》

模拟不熟悉品牌的 Amazon 消费者，检查主图识别、Title 前半段、第一核心购买理由、第一差异化、主图与 Title、前两张副图、信息密度、认知冲突、真实性疑问和继续阅读理由。考虑移动端 Title/Bullet 前部、图片文字大小和信息顺序；无真实设备预览时标记 `[移动端实际显示待验证]`，不得声称已验证全部移动端显示。必须回答：只看主图 + Title 前半段 + 前两张副图，消费者是否知道这是什么、为什么值得买、最重要区别是什么？

### 《文案—视觉一致性检查》

逐项核对 Title × 主图、P0 × 前两张副图、Bullet × 副图、文案/视觉 Claim、数字、材料、尺寸、配件数量、使用方法、安装逻辑、Description/A+ × 图片/A+、视频 × 文案 Claim。状态只用 `【一致】`、`【部分一致】`、`【存在冲突】`、`【信息缺失】`、`【无法验证】`，不使用百分制一致性评分。材料、数字、尺寸、配件或安装冲突按事实问题处理。

### 《购买路径完整性检查》

检查：这是什么 → 为什么适合我 → 解决什么问题 → 为什么更好 → 为什么相信 → 怎么使用 → 是否适合场景 → 主要顾虑是否解决 → 为什么值得购买。只标记真实断点：`【产品识别断点】`、`【价值理解断点】`、`【差异化断点】`、`【信任断点】`、`【使用理解断点】`、`【适配断点】`、`【顾虑解除断点】`、`【购买理由断点】`。页面长短应随产品复杂度调整。

### 《最终Claim审核表》

合并 5-2 Claim—Evidence、5-3 视觉 Claim—Evidence 和真实页面实际表达。至少记录 Claim、实际位置、文案表达、视觉表达、证据来源/类型、证据状态、文案强度、视觉强度、是否一致、是否保留、是否弱化、是否删除和风险。图片夸张重量、危险场景、测试动画、箭头或结构表现同样是 Claim。最终状态只用 `【保留】`、`【弱化】`、`【补证据后使用】`、`【删除】`、`【无法确认】`。实际页面出现 Customers Love、Top Choice、Best/#1、100%、Never、Guaranteed、Certified、Patented、Waterproof、Fireproof、Heavy Duty、Load Capacity、医疗/健康/儿童安全等高风险表达时，逐项审核，不为页面没出现的风险制造问题。

### 《SEO与可读性审核》

检查核心产品词自然覆盖、关键词堆砌和同义重复、Title 复杂度、Bullet 长度与前置信息、Description/A+重复、图片文字密度/字号、AI 营销腔、中式英语和过度形容词。不要输出 SEO/Conversion 百分制评分；只指出会影响理解、点击、信任、转化、真实性、一致性或合规的实际问题。

### 《页面真实性检查》

检查图片和视频的产品结构、数量、配件、材料、尺寸、安装逻辑、使用场景、动作、比例和物理关系；若明显使用 AI，专项检查零件变形、漏件/多件、连接错误、左右异常、文字乱码、反射/影子不一致、场景物理错误和比例错误，但不得为了找问题而编造错误。无可靠 Amazon 政策资料时输出 `[Amazon政策专项核对待执行]`，不声称“100%符合最新政策”。

### 《页面优化优先级》和《最终修改清单》

只使用页面优化优先级：

- `【P0｜必须改】`：事实错误、产品识别错误、战略严重偏离、无证据核心 Claim、视觉夸大、结构/安装错误、数字/材料冲突、严重影响理解或高风险表达。
- `【P1｜强烈建议改】`：首张副图顺序、核心价值过弱、信任链不足、Bullet 重复、证据过后、重要顾虑未处理。
- `【P2｜可优化】`：文案精简、局部美化、次要场景、A+和品牌完善。

这里的 P0/P1/P2 是页面优化优先级，不是 3-1 产品机会优先级。每项修改必须有编号、优先级、模块、当前问题、证据、为什么是问题、影响（理解/信任/点击/转化/真实性/合规/一致性）、修改方向、责任 Skill（5-1/5-2/5-3/4 阶段/3 阶段）和修改后验证方式。没有明确业务影响就不要列为重要修改项；不要因局部问题推倒整套页面。

### 《反方检查》

至少回答：核心战略是否仍清晰；P2 是否抢 P0；前 5 秒是否成立；文案和视觉是否一致；Claim 是否超证据；图片暗示是否绕过规则；真实结构/场景是否正确；是否有移动端或信息过载问题；是否把风格偏好当 P0/P1；是否重复审核制造纯风格问题；为什么采用当前结论。

## 最终状态与 6-1 交接

只允许：

- `【页面通过｜可上线/进入推广】`
- `【有条件通过｜完成P0修改后上线】`
- `【需要优化｜修改后重新审核】`
- `【关键Claim或产品事实冲突｜暂不建议上线】`
- `【页面成品不足｜暂无法完成正式审核】`

只有页面战略、核心文案/视觉、关键 Claim 与真实产品事实已无阻断性问题，且状态为页面通过或有条件通过时，才生成《6-1输入交接包》。交接包至少包含页面核心卖点、关键词、Claim 及证据状态、消费者顾虑、页面弱点和推广阶段待验证假设；不越权设计广告方案。关键冲突、页面成品不足或需要优化时只输出修改清单，不生成 6-1 交接包。

6. 《文案—视觉一致性检查》

正式 HTML 成功写入、确认文件存在且命名正确后，才调用 `hzp-amz-0-2-report-index`，原样传递本次 Product Code、Products Root、Product Root。5-4 不得扫描、生成、排序、维护或备用更新 `index.html`。报告失败不调用 0-2；报告成功但 0-2 失败时保留报告并明确“正式报告：生成成功；报告索引：更新失败；原因：[实际原因]”。

## 绝对禁止

禁止脱离 5-1 重做页面战略；脱离 5-2/5-3 偷改文案或视觉战略；重新开发产品；把风格偏好升级为业务问题；编造 Claim、测试、消费者评价、AI 错误或政策结论；以图片暗示绕过证据；伪造竞品缺陷；修改 `03_产品页面思路.md`、`07_产品资料` 原始成品/素材、历史 HTML 或 `index.html`；复制 0-2 索引逻辑；直接做广告方案；因局部问题推倒全部页面。

详细字段和报告结构见 `references/audit-framework.md`、`references/handoff-schema.md` 和 `templates/report-outline.md`。
