# HZP Amazon 4-2｜量产前检查

## 定位与边界

4-2 回答：“已经通过 4-1 样品评审的产品，现在是否真的准备好做大货？”

- 4-1 = 样品是否做对；4-2 = 是否准备好量产。
- 只做量产前冻结与放行检查，不重新做市场分析、产品开发、重新打样、最终验货、采购执行或库存管理。
- 一次运行连续完成所有已定义检查，不要求用户逐阶段确认。
- 只写有证据支持的事实；将分析推断、供应商确认和待验证事项分开。

## 产品身份和版本输入

1. 使用本次已确认的 Product Root，读取 01_产品档案.md，取得产品代码、中文名称、Marketplace 和身份字段。缺失、冲突或无法确认时停止并输出 [产品档案缺失]、[产品身份冲突] 或 [产品身份无法确认]；禁止根据 ASIN、目录名或报告名猜名称。
2. 只在同一 Product Root 的 06_SKILL分析报告/ 递归查找当前产品最新有效的 4-1 正式 HTML；不得跨 Product Root 读取。
3. 候选报告必须匹配当前产品代码和 Skill 编号，并符合 4-1_[产品编号]_打样评审_V[版本号]_[YYYYMMDD]_[HHMMSS].html。先取最大 V，同 V 取文件名时间戳最大者；禁止依赖文件系统时间、目录顺序或找到的第一个文件。
4. 排除 index.html、Draft、Preview、Test、Temp、Demo、Debug、失败、未完成、废弃、无效和临时文件。无版本号或无文件名时间戳的旧文件只能作为历史参考并明确标注。
5. 优先读取最新 4-1 的《4-2输入交接包》。按需回查最新有效的 3-3、3-2、3-1，仅用于核对冻结要求、P0/P1、核心消费者价值和是否出现未经批准的变化，不重新完整执行上游 Skill。
6. 正式 HTML 必须有《输入版本追溯》，只记录本次实际读取的上游报告：Skill 编号、中文名、实际文件名、版本号、文件名生成时间、输入类型（【核心输入】/【辅助回查】/【历史版本对照】）和本次用途。

## 4-1 状态门槛

- 【通过｜进入4-2量产前检查】：正常执行。
- 【有条件通过｜完成指定修正后进入4-2】：逐项找到条件完成证据；任一条件未完成或无法确认，输出 [4-1进入4-2条件尚未完成]，不得放行量产。
- 【修改后重打】、【退回3-2重新开发】、【证据不足｜暂无法完成样品评审】：不得执行正式量产放行；生成说明和重新运行条件。
- 4-1 没有有效最终状态或最新版无法确认时，停止并说明原因。

## 真实量产资料发现

在当前 Product Root 的 07_产品资料/ 内主动查找与量产直接相关的真实资料：最终样品与轮次、量产 BOM、规格表、工程图、尺寸/公差、材料牌号/等级/证明、工厂或供应商确认、最终报价、MOQ、交期、模具/治具、工艺、CMF、包材与包装结构、标签/条码/警示、测试/认证/合规、质量标准、验货/AQL、首件确认、修改记录和供应链风险。先理解量产决策需要回答的问题，再读取相关文件；文件名只是线索，实际字段、内容和日期才是证据。不要无目的扫描整个硬盘。

证据状态统一使用：[FACT] 数据/文件/人工确认支持；[INFERENCE] AI 分析推断；[TO-VERIFY] 待验证；[DECISION] 已确认决策。

量产检查可用的展示标签： 【已确认】、【部分确认】、【待确认】、【存在冲突】、【量产前必须解决】、【首批量产重点监控】、【后续持续监控】。

供应商确认可以证明供应链声明，但不能冒充真实大货稳定性；图片外观不能证明材料牌号；AI 建议不能成为最终规格；理论成本不能冒充报价；没有正式 AQL/缺陷标准时不得编造。

## 固定执行流程

读取身份 → 读取最新有效 4-1 → 检查 4-1 门槛和《4-2输入交接包》 → 发现并核实 07_产品资料 量产资料 → 按需回查 3-3/3-2/3-1 → 最终产品定义 → BOM/规格/材料 → 成本/供应链 → 质量/验货 → 包装/运输 → IP/合规/安全 → 量产风险 → 量产前冻结清单 → 变更控制规则 → 反方检查 → 量产放行决策 → 生成正式 HTML → 确认落盘 → 调用 hzp-amz-0-2-report-index。

## 必须检查的项目

### 1. 最终产品定义检查

明确产品代码、名称、最终样品身份、样品轮次、4-1 版本、3-3 版本、3-2 方案和当前量产定义。逐项比较量产版与 4-1 通过样品是否保持 P0/P1、核心消费者价值、核心购买理由、核心结构、材料、功能、配件、工艺、CMF 和包装。表格至少包含：项目、4-1通过状态、当前量产状态、是否一致、变化原因、是否影响 P0/P1、是否需要重新验证。

发现核心结构、核心材料、核心功能、核心使用方式、P0 逻辑、核心差异化或安全设计发生重大变化时，不得直接量产：需要真实样品验证的退回 4-1，需要重新开发的退回 3-2。

### 2. 量产 BOM、关键规格与材料

生成《量产BOM检查》和《关键规格冻结检查》。BOM 至少检查零件名称/编号、数量、材料、规格、表面处理、供应来源、关键质量要求和状态。关键规格只检查当前产品相关的尺寸、公差、重量、材料牌号、厚度、强度、容量、功率、连接、配件和安全参数。

最终 BOM、规格、材料必须来自项目文件、工程确认、供应商确认、实测、正式规格文件或人工确认。3-2 的方案建议在没有上述证据前只能写 [关键规格待确认]；不得自动升级为量产规格。关键 BOM 不清楚时写 [量产BOM待确认]。材料“看起来像”某牌号不算确认。

### 3. 成本和供应链

生成《量产成本确认》和《量产供应链检查》。检查目标成本、真实报价及日期/来源、数量/MOQ、包材、模具/治具、特殊工艺、额外费用、成本敏感项、供应商、工艺能力、材料来源、交期、产能和替代方案。真实供应商报价可作为证据；理论估算标记 [分析推算｜成本待确认]，没有最终报价标记 [量产成本待确认]。供应商“可以”只记为 [供应商确认]，不能写成真实量产验证。

### 4. 质量标准、包装和运输

生成《质量标准与验货要求》和《量产包装检查》。质量标准覆盖核心功能、尺寸、材料、外观、工艺、装配、配件、包装、标签和安全。没有正式标准写 [量产质量标准不足]、[质量标准待建立]；没有项目 AQL 时不得擅自编造 AQL，可建议定义 Critical/Major/Minor。

检查包装结构、内外包装、防护、配件、说明书、标签、条码、警示、尺寸/重量、运输风险、跌落测试和易损件保护。缺资料写 [包装待确认]；没有真实 Amazon/FBA 要求时写 [Amazon包装要求待核对]，不得声称完全符合所有要求。

### 5. IP、合规、安全和量产风险

生成《IP / 合规 / 安全检查》，分别标记 【已确认】、【部分确认】、【待验证】、【存在明确风险】。没有正式专利检索/律师意见/内部审核只能写 [IP风险待验证]；没有测试、认证或法规资料只能写 [合规待确认]。已确认的重大安全风险必须在量产前解决。

生成《量产风险清单》，关注材料批次、公差累积、装配一致性、色差、包装运输、替料、漏装、产能、交期、良率和抽检。按 【量产前必须解决】、【首批量产重点监控】、【后续持续监控】 分类，不使用伪精确风险分数。

## 量产前冻结和变更控制

必须生成《量产前冻结清单》，分为：
- 【A｜已冻结】：只有项目文件、工程/供应商/人工确认或 4-1 真实通过证据支持的内容才能进入。
- 【B｜量产前必须完成】：最终报价、BOM/规格/材料、合规、包装测试、质量标准、工厂确认等未完成事项。
- 【C｜不得未经重新评审修改】：P0/P1 逻辑、核心消费者价值、核心结构/材料/功能、安全设计和核心使用方式。

同时生成《量产变更控制规则》：供应商提出材料、结构、尺寸、公差、零件、功能或包装变化时，先判断是否为核心变化；未经批准不得替料、减件、改厚度、改结构或改工艺。核心变化原则上退回 4-1 重新验证，核心方案不可行或需大幅改变时退回 3-2。不得因“看起来合理”自动冻结。

## 反方检查与最终状态

《反方检查》至少回答：最支持量产的证据、最大风险、是否把样品通过当成大货稳定、是否把供应商承诺当验证、是否把 AI 建议当规格、关键 BOM/质量标准/材料替换/IP/合规/安全是否仍有缺口、现在下大货最可能造成的损失及为何仍作当前决策。

最终只允许：
1. 【通过｜允许进入量产】
2. 【有条件通过｜完成指定事项后量产】
3. 【暂缓量产｜补齐关键条件】
4. 【退回4-1重新验证】
5. 【退回3-2重新开发】

通过要求产品定义稳定、核心 BOM/规格/材料/供应链/成本可执行、质量和包装基本建立，且没有未解决的重大安全/IP/合规问题或需要重新打样的核心变化。有条件通过必须列出事项、责任方、完成证据和完成标准；否则使用暂缓量产。禁止“样品通过即默认量产”。

正式 HTML 写入并确认文件存在、文件名正确后，才调用 hzp-amz-0-2-report-index，原样传递本次已确认的 Product Code、Products Root、Product Root。4-2 不得扫描、生成、排序、维护或备用更新 index.html。报告失败不调用 0-2；报告成功但 0-2 失败时保留报告并返回“正式报告：生成成功；报告索引：更新失败；原因：[实际原因]”。

## 绝对禁止

禁止编造 BOM、规格、材料、成本、报价、AQL、供应链能力、IP/合规结论或测试结果；禁止把图片/AI/供应商承诺冒充实测、材料确认或量产验证；禁止忽略安全硬风险；禁止未经批准替料或修改核心设计；禁止重新开发产品、修改历史报告/原始资料或自行维护 index.html。

详细字段见 references/preproduction-framework.md；报告结构见 templates/report-outline.md。
