# HZP Amazon 3-1｜产品机会定义

## 职责边界

本 Skill 回答“我们最值得抓住的产品机会是什么，以及为什么值得做”。它基于 2-1 产品分析、2-2 细分市场分析和 2-3 人工判断与 AI 同步，收敛消费者未满足需求、团队约束和商业意义。它不重新全面执行 2-1/2-2，不替人工重写观点，不直接设计材料、精确尺寸、BOM、连接细节、模具、工艺参数或最终结构；这些属于后续 3-2 的 HOW。

## 输入与产品身份

1. 从 `[Product Root]/01_产品档案.md` 读取产品编号和产品中文名称。报告标题与身份卡必须使用“产品机会定义｜产品编号 产品中文名称”。禁止从 ASIN、Niche、文件名或目录名猜名称；档案缺失输出 `[产品档案缺失]` 并停止，身份冲突输出 `[产品身份冲突]` 并列出冲突字段后停止。
2. 在 `[Product Root]/06_SKILL分析报告/` 识别同一产品最新有效的 2-1、2-2、2-3 正式 HTML，按标准文件名的版本号和时间排序，历史报告只作为回查证据。2-3 存在时优先读取其中《3-1输入交接包》，不得绕过它自由重写人工结论。
3. 原则上不重新分析 CSV、Excel、Keepa、Cerebro、Reviews 或其他 `05_分析源数据`。仅在前序报告有明确冲突，或需要核实影响机会定义的关键证据时回查源数据；回查结果注明来源和证据状态。

## 2-2 市场决策闸门

## 上游正式报告选择与输入版本追溯（统一协议）

凡本 Skill 读取其他 Skill 生成的正式分析报告，均只在当前已锁定 Product Root 的 `06_SKILL分析报告/` 内递归查找，不得跨 Product Root。候选文件必须同时匹配当前产品编号和目标 Skill 编号，并优先符合正式命名：

`[Skill编号]_[产品编号]_[技能中文名称]_V[版本号]_[YYYYMMDD]_[HHMMSS].html`

选择时解析 Skill 编号、产品编号、`V` 版本号和文件名时间戳；先取最大版本号，同版本再取文件名时间戳最大的文件。不得依赖目录顺序、文件系统返回顺序、modified time、created time 或“找到第一个就使用”。例如当前产品为 N24、目标为 2-2，只能候选 `2-2_N24_*.html`，不得读取 N25、A01 或其他产品。

只使用“最新有效正式版本”。`index.html`、Draft、Preview、Test、Temp、Demo、Debug、失败、未完成、废弃、无效或临时输出不得作为正式输入；无版本号或无文件名时间戳的旧文件只能作为历史参考，不能替代版本化正式报告。若最新候选的有效性无法可靠确认，输出 `[上游报告有效性无法确认]`，列出目标 Skill、候选文件名和无法确认原因，不得偷偷退回旧版。若认为最新版可能有错误或数据异常，仍以最新版为当前输入并标记 `[建议复核上游最新版]`。

默认正式结论只使用每个目标 Skill 的最新有效版本，不与旧版拼接、平均或混合。只有明确调查版本变化时才读取旧版，并在报告中标记 `[历史版本对照]`，且不改变当前正式输入。辅助回查与核心输入使用同一选择规则。

凡本次实际读取了上游正式报告，HTML 必须增加固定章节《输入版本追溯》，逐条记录：上游 Skill 编号、上游 Skill 中文名称、实际读取文件名、版本号、文件名生成时间、输入类型（`【核心输入】` / `【辅助回查】` / `【历史版本对照】`）和本次用途。未实际读取的报告不得写入追溯；非版本化的 `01_产品档案.md`、`02_产品开发思路.md`、`05_分析源数据/`、`07_产品资料/` 继续沿用原读取规则。

必须读取 2-2 Stage 7 市场进入决策并原样继承相关条件：

- `NO-GO`：原则上停止正式产品机会定义，输出 `[市场进入决策为NO-GO]`，不得绕过市场决策。
- `CONDITIONAL GO`：允许执行，但所有“GO 前必须验证的条件”必须进入《风险与关键验证项》和《3-2输入交接包》；不得升级为 GO。
- `GO`：正常执行机会收敛。
- `INSUFFICIENT EVIDENCE｜证据不足`：不正式输出 P0；可整理候选机会和证据缺口，并标记 `[前序市场证据不足]`。

3-1 不重新计算或改变 2-2 的 GO / CONDITIONAL GO / NO-GO。

## 继承规则

从 2-1 继承对标产品问题、Review 证据、产品层缺陷、Product Definition V1、开发方向、风险和待验证项；“开发建议”只能作为候选输入。从 2-2 重点继承主进入市场、真实需求、商业价值、竞争壁垒、Stage 5 未满足需求、Stage 6 切入机会、Stage 7 决策、关键风险和 GO 前条件。从 2-3 固定继承《3-1输入交接包》的项目约束、专家判断、产品/商业假设、重大冲突和关键验证事项。所有标签按原报告保留，`[分析推断]` 不得升级为 `[数据支持]`。

## 产品机会证据链

候选机会必须尽量通过以下链条：真实消费者问题 → 不是单一 ASIN 偶发现象 → 市场未充分解决 → 可由产品本身解决 → 消费者能感知改善 → 能形成购买理由 → 团队/供应链具备基本实现可能 → 没有已确认不可接受的致命风险。综合考虑真实需求、市场共性、未满足程度、可产品化、可感知性、购买理由、团队匹配、商业意义和风险可接受性。

不得把“提升体验、提高品质、做得高级、比竞品更好、提升性价比”直接当作机会；必须说明解决谁的什么问题、为什么是市场机会、消费者为什么在意。多个改动若服务同一底层需求（例如材料、连接件、固定点都解决稳定性），先合并为一个机会，具体 HOW 留给 3-2。不得按 Review 次数机械决定 P0，也不得强制凑 3 个或 5 个机会。

## 候选池与筛选

先生成《候选产品机会池》，候选可来自 2-1 产品问题、2-2 未满足需求/切入机会、2-3 人工判断/假设/约束。每个候选至少记录：机会名称、消费者问题、目标消费者和场景、消费者价值、2-1/2-2/2-3 证据、市场共性、未满足程度、可产品化程度、可感知性、购买理由、团队/供应链匹配度、商业意义、风险、待验证事项和当前状态。

《机会筛选与合并》必须解释来源、关键证据、状态及保留/合并/淘汰原因，并说明对 3-2 的影响。状态只允许：`【保留】`、`【合并】`、`【待验证】`、`【淘汰】`。正式机会优先级只使用 `P0｜核心产品机会`、`P1｜辅助产品机会`、`P2｜储备产品机会`，不生成 78/100 等伪精确综合分。若证据不足，输出 `【暂无值得正式定义的产品机会】`，不要人工制造差异化方向。

## 正式机会定义（WHAT + WHY）

每个保留的正式机会必须说明：优先级、机会名称、消费者核心问题、目标消费者、核心场景、当前未满足需求、消费者价值、市场层证据、产品层证据、人工/专家输入、市场共性、为什么未充分解决、为什么值得我们做、为什么可能形成购买理由、消费者如何感知、团队/供应链匹配条件、项目约束、风险、未知/待验证、机会结论和下一阶段任务。机会描述不能写成最终材料、厚度、尺寸、结构或工艺方案；例如用“提升结构稳定性与长期可靠性”描述机会，具体怎么实现交给 3-2。

## 正式 HTML 输出

输出到 `[Product Root]/06_SKILL分析报告/`，只新增、不覆盖历史文件：

`3-1_[产品编号]_产品机会定义_V[最大版本号+1]_[YYYYMMDD]_[HHMMSS].html`

正式报告固定包含：

1. 产品身份与机会结论
2. 前序决策依据
3. 《候选产品机会池》
4. 《机会筛选与合并》
5. 《正式产品机会定义》
6. 《风险与关键验证项》
7. 《3-2输入交接包》
8. 数据与证据局限
9. 名词术语解释

首页依次展示产品编号与名称、2-2 市场进入决策、一句话机会结论、P0、P1、最强支持证据、最大风险、最大待验证事项和下一步 3-2。使用中文优先的机会卡片、矩阵、证据表和风险表；不生成无意义雷达图、伪量化综合分、花哨动画或 3D 图表。

## 风险、交接与 0-2

《风险与关键验证项》必须继承 2-2 CONDITIONAL GO 条件、2-2 风险、2-3 重大冲突和待验证假设，并加入 3-1 新发现缺口；每项写验证主题、重要性、已知证据、未知部分、验证方式和失败对机会的影响。

《3-2输入交接包》是 HTML 内固定章节，不另造重复报告，至少传递 P0/P1 机会、目标消费者、核心场景、必须解决的问题、消费者应获得的价值、购买理由、项目约束、已确认团队/供应链条件、不得当事实的假设、重大风险和必须验证事项。它只说解决什么和为什么，不替 3-2 规定怎么解决。

正式 HTML 成功写入并确认存在后，调用 `hzp-amz-0-2-report-index`，原样传递 Product Code、Products Root 和 Product Root。3-1 不生成、扫描、排序、维护或备用更新 `index.html`。若 0-2 失败，保留正式报告并报告“正式报告：生成成功；报告索引：更新失败；原因：[实际原因]”。

## 绝对禁止

禁止重新完整执行 2-1/2-2，绕过 2-3 编造人工意见，把单 ASIN 问题直接当市场机会，把具体方案当机会，强制凑机会数量，按 Review 次数机械定 P0，改变 2-2 市场决策，修改前序报告或 `02_产品开发思路.md`，直接完成详细产品设计、BOM、最终结构或工艺参数，或在未授权下下单、量产、联系供应商。

详细候选池、证据链和筛选规则见 [references/opportunity-framework.md](references/opportunity-framework.md)；3-2 交接字段见 [references/handoff-schema.md](references/handoff-schema.md)；报告顺序见 [templates/report-outline.md](templates/report-outline.md)。
