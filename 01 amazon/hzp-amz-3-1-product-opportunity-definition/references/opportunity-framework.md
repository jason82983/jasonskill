# 产品机会框架

## 候选机会字段

每个候选机会记录：机会名称、消费者问题、目标消费者/场景、消费者价值、2-1 证据、2-2 证据、2-3 人工输入、市场共性、未满足程度、可产品化程度、消费者可感知性、购买理由、团队/供应链匹配度、商业意义、主要风险、待验证事项和状态。

## 证据链检查

真实消费者问题 → 非单一 ASIN 偶发现象 → 市场未充分解决 → 产品可解决 → 消费者可感知 → 形成购买理由 → 基本实现可能 → 无已确认致命风险。任何一环缺失都要降低状态为 `【待验证】` 或 `【淘汰】`，不得用经验值补齐。

## 合并规则

材料、厚度、连接件、固定点等若都在解决同一底层需求，应合并为一个机会；具体 HOW 不进入机会定义。不能把多个微小工程动作包装成多个产品机会。

## 状态和优先级

候选状态只使用 `【保留】`、`【合并】`、`【待验证】`、`【淘汰】`。正式机会优先级只使用 P0、P1、P2。P0 需要较完整证据链并能构成核心购买理由；P1 是有价值的辅助机会；P2 证据较弱、风险较高或商业意义有限。不要强制生成固定数量，也不要生成综合评分。
