# 4-1 输入交接包字段

只有【通过｜进入打样】或【有条件通过｜完成指定事项后进入打样】时，才生成本交接包。它是打样验证输入，不是工程定版或量产批准。

## 评审结论

- 评审状态与一句话结论
- 本次批准进入打样的 3-2 方案及来源版本
- P0/P1 解决情况、消费者价值、核心购买理由和差异化判断
- 工程、成本、供应链、IP、合规判断
- 最大风险、最大待验证项和下一步动作

## 打样边界

### 打样必须实现

列出来自 P0/P1、3-2 设计目标和本次评审的核心结构、材料、规格、功能、配件和价值要求。

### 打样建议实现

列出可提高体验但不应破坏核心 P0/P1 的项目，并保留状态。

### 禁止偏离

列出不得未经重新评审删除或改变的核心差异化、P0 解决逻辑、核心使用方式和产品定义。

## 方案定义与验证

- 产品定义、P0/P1、消费者和场景
- 核心结构、材料、关键规格、功能、配件
- BOM V1 状态、工艺方向、CMF、包装打样要求
- 工程、结构、材料、功能、使用体验、消费者感知、CMF 验证
- 待确认成本、供应链、IP、合规和其他风险
- 样品成功判定条件
- 样品失败判定条件
- 样品阶段允许调整范围
- 核心内容变更时返回 3-2/3-3 的触发条件

每个字段都记录证据来源和状态。无法量化时使用明确的定性标准，并标记 `[打样待验证]`；不得凭空创造上游没有依据的指标。
