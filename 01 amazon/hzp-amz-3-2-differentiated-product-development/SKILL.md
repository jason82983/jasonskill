# HZP Amazon 3-2｜差异化产品开发

## 定位与边界

3-2 回答：“3-1 已确认的机会，具体应该做成什么产品方案？”它负责 HOW 的开发阶段定义，输出可评审、可打样、可验证的《推荐差异化产品方案 V1》。

职责边界固定为：3-1 = WHAT + WHY；3-2 = HOW；3-3 = 方案评审；4-1 = 样品验证。3-2 不重新做 2-1/2-2 市场分析，不重新定义 3-1 机会，不直接给出最终工程定版、最终量产 BOM、最终供应商报价、最终质量标准或量产放行。

## 产品身份与输入

1. 从 `[Product Root]/01_产品档案.md` 读取产品代码和产品中文名称。产品档案缺失、身份冲突或无法安全确定时停止，分别输出 `[产品档案缺失]` 或 `[产品身份冲突]`，列出冲突字段；禁止根据 ASIN、目录名或文件名猜产品身份。
2. 在同一 Product Root 的 `06_SKILL分析报告/` 找到最新有效的 3-1 正式 HTML，按文件名版本和时间排序；优先读取其中的《3-2输入交接包》。它是主要开发入口，必须继承 P0/P1 机会、目标消费者、场景、消费者问题、价值、购买理由、项目约束、已确认条件、假设、风险和验证事项。
3. 按需回查最新 2-3、2-1、2-2，只为核实具体设计依据、证据冲突或关键限制，不重新完整执行前序 Skill，也不静默覆盖前序结论。保留 `[数据支持]`、`[分析推断]`、`[待验证]`、`[已确认]` 等证据状态；AI 推断不得升级为事实。
4. 主动检查 `[Product Root]/07_产品资料/`。按需读取真实图片、样品、结构、尺寸、工厂/供应商、工艺、材料、报价、包装和测试资料；没有资料时使用 `[工程待验证]`、`[成本待验证]`、`[供应链待验证]`，不得假装已有能力或报价。

## 上游正式报告选择与输入版本追溯（统一协议）

凡本 Skill 读取其他 Skill 生成的正式分析报告，均只在当前已锁定 Product Root 的 `06_SKILL分析报告/` 内递归查找，不得跨 Product Root。候选文件必须同时匹配当前产品编号和目标 Skill 编号，并优先符合正式命名：

`[Skill编号]_[产品编号]_[技能中文名称]_V[版本号]_[YYYYMMDD]_[HHMMSS].html`

选择时解析 Skill 编号、产品编号、`V` 版本号和文件名时间戳；先取最大版本号，同版本再取文件名时间戳最大的文件。不得依赖目录顺序、文件系统返回顺序、modified time、created time 或“找到第一个就使用”。例如当前产品为 N24、目标为 2-2，只能候选 `2-2_N24_*.html`，不得读取 N25、A01 或其他产品。

只使用“最新有效正式版本”。`index.html`、Draft、Preview、Test、Temp、Demo、Debug、失败、未完成、废弃、无效或临时输出不得作为正式输入；无版本号或无文件名时间戳的旧文件只能作为历史参考，不能替代版本化正式报告。若最新候选的有效性无法可靠确认，输出 `[上游报告有效性无法确认]`，列出目标 Skill、候选文件名和无法确认原因，不得偷偷退回旧版。若认为最新版可能有错误或数据异常，仍以最新版为当前输入并标记 `[建议复核上游最新版]`。

默认正式结论只使用每个目标 Skill 的最新有效版本，不与旧版拼接、平均或混合。只有明确调查版本变化时才读取旧版，并在报告中标记 `[历史版本对照]`，且不改变当前正式输入。辅助回查与核心输入使用同一选择规则。

凡本次实际读取了上游正式报告，HTML 必须增加固定章节《输入版本追溯》，逐条记录：上游 Skill 编号、上游 Skill 中文名称、实际读取文件名、版本号、文件名生成时间、输入类型（`【核心输入】` / `【辅助回查】` / `【历史版本对照】`）和本次用途。未实际读取的报告不得写入追溯；非版本化的 `01_产品档案.md`、`02_产品开发思路.md`、`05_分析源数据/`、`07_产品资料/` 继续沿用原读取规则。

读取身份 → 读取最新 3-1 → 优先读取《3-2输入交接包》 → 按需回查 2-1/2-2/2-3 → 检查 07_产品资料 → 机会与约束继承 → 产品设计目标 → 候选解决方案 → 机会—设计追溯 → 方案比较与筛选 → 推荐差异化产品方案 V1 → Amazon 可表达差异点 → 风险与验证计划 → HTML 内《3-3输入交接包》 → 确认报告落盘 → 调用 0-2。

### 1. 机会与约束继承

先完整列出 P0 核心机会、P1 辅助机会、目标消费者、核心场景、消费者问题、消费者价值、购买理由、项目硬约束、人工确认事项、重大风险和待验证事项。不得先入为主地设计；任何新增设计都必须能追溯到 P0/P1、硬约束或安全/合规/制造必要条件。

### 2. 产品设计目标

生成《产品设计目标》，至少包含：P0/P1 对应目标、必须实现、应尽量实现、不应牺牲、项目硬约束、设计禁区、消费者必须感知的价值和必须形成的购买理由。目标先描述“必须做到什么”，不要把目标直接写成最终材料、精确尺寸或最终结构。

### 3. 候选解决方案

只有完成设计目标后才进入 HOW。根据证据提出一个或多个合理方案；不强制凑数量。允许讨论产品结构、材料方向、关键尺寸/规格建议、功能/配件组合、BOM V1、工艺与连接方向、使用/安装方式、CMF/外观、包装、体验、Amazon 表达差异和成本目标，但每项必须标明状态。

允许状态：`[已确认]`、`[项目约束]`、`[方案建议]`、`[工程待验证]`、`[成本待验证]`、`[供应链待验证]`、`[IP风险待验证]`、`[合规风险待验证]`、`[消费者价值待验证]`、`[证据不足]`。状态不允许把 AI 方案建议伪装成已确认事实。

不得编造工厂工艺、良率、交期、成本、IP 无风险、法规完全合规或工程测试结果。目标成本只有在来自项目约束时才可写明；理论估算必须标记 `[分析推算｜成本待验证]`。未知不等于失败。

### 4. 机会—设计追溯

必须生成《机会—设计追溯矩阵》。每个重要设计项至少说明：设计项、对应 P0/P1 机会、对应消费者问题、设计目标、消费者如何感知、如何形成购买理由、当前状态和验证要求。无法解释“为什么需要这个设计”的功能原则上删除，避免无来源功能堆砌和为增加功能而增加成本/复杂度。

### 5. 方案比较与筛选

多个方案按以下维度用证据和文字判断比较：P0/P1 解决能力、消费者感知性、购买理由强度、差异化真实性、Amazon 页面表达能力、工程可行性、成本影响、供应链可行性、质量风险、IP 风险、合规风险和验证难度。禁止 87/100、AI 信心分、雷达综合分等伪精确评分。

候选方案状态只允许：`【推荐】`、`【备选】`、`【待验证】`、`【淘汰】`。推荐方案必须做反方检查：为什么推荐、为什么不是主要备选、最大弱点、未验证假设、什么结果会推翻主方案、主方案失败时切换哪个备选。若 P0 无法转化为合理设计、关键条件完全未知且无法提出合理路径、关键约束冲突、存在已确认致命 IP/合规/安全风险或证据不足以选择路径，不得强行推荐，输出【当前无法形成可靠推荐方案】并说明缺口、验证责任人和重跑条件。

## 正式报告内容

生成中文优先的正式 HTML，保存到 `[Product Root]/06_SKILL分析报告/`，不覆盖历史报告：

`3-2_[产品编号]_差异化产品开发_V[最大版本号+1]_[YYYYMMDD]_[HHMMSS].html`

报告固定包含：

1. 产品身份与开发结论
2. 3-1 机会与约束继承
3. 《产品设计目标》
4. 《候选差异化方案》
5. 《机会—设计追溯矩阵》
6. 《方案比较与筛选》
7. 《推荐差异化产品方案 V1》
8. 《Amazon可表达差异点》
9. 《风险与验证计划》
10. 《3-3输入交接包》
11. 数据与证据局限
12. 《名词术语解释》

首页优先展示产品代码+名称、3-1 P0 机会、一句话开发结论、推荐方案 V1 核心定义、最重要差异化、消费者价值、核心购买理由、最大风险、最大待验证事项和下一步 3-3。图表只在有实际数据意义时使用；优先产品方案卡片、追溯矩阵、方案比较表、BOM 表和风险验证表，禁止花哨动画、3D 图表和伪精确评分。

《推荐差异化产品方案 V1》至少覆盖：产品定义、消费者/场景、P0/P1、设计原则、结构、材料、关键规格、功能、配件、BOM V1、工艺、使用/安装、CMF/外观、包装、差异化、消费者价值、购买理由、Amazon 卖点、成本目标/状态、供应链要求、工程/IP/合规状态、最大风险和待验证事项。BOM V1 必须明确“开发阶段 BOM，不是最终量产 BOM”；未确认的零件、材料、规格、数量标记 `[方案建议]` 或 `[工程待验证]`，不得补造零件。

《Amazon可表达差异点》逐项说明产品差异点、消费者价值、购买理由及适合通过主图、副图、视频、A+、标题/五点中的哪种方式表达；3-2 不负责正式 Listing 制作。

《风险与验证计划》至少覆盖工程、结构、材料、功能、使用体验、成本、供应链、质量、IP、合规和消费者价值验证。每项写验证主题、重要性、已知、未知、建议方式、失败影响、影响设计项及影响 P0/P1。

《3-3输入交接包》固定放在 HTML 末尾，传递推荐方案 V1、推荐理由、对应机会、消费者/场景、结构、材料、规格、功能、配件、BOM V1、工艺、CMF、包装、价值、购买理由、Amazon 差异点、已确认事项、项目约束、方案建议、各类待验证状态、主方案弱点、备选方案、推翻条件和必须验证事项。它服务于 3-3 评审，不是最终工程批准。

## 0-2 联动与文件职责

正式 HTML 成功写入并确认文件存在、文件名正确后，调用 `hzp-amz-0-2-report-index`，传递本次已经确认的同一个 Product Code、Products Root、Product Root。3-2 只负责分析和正式报告，不扫描、生成、维护、排序或备用更新 `index.html`。报告失败时不调用 0-2；报告成功但 0-2 失败时保留报告，并明确返回“正式报告：生成成功；报告索引：更新失败；原因：[实际原因]”。

## 禁止事项

禁止重新做 2-1/2-2，绕过 3-1 自行增加新的核心机会，修改前序报告或人工原始资料，把具体设计建议冒充已确认工程事实，编造真实成本/报价/供应链能力/IP/合规结论，强制生成多个方案，用伪精确评分选方案，把未知写成失败，直接输出最终工程图、最终公差、最终模具参数、最终量产 BOM、最终供应商报价、最终质量标准或量产放行，也禁止自行维护 `index.html`。
