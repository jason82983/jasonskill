# HZP Amazon 1-1｜商机发现

## 定位与边界

本 Skill 回答“哪里存在值得继续验证的需求—产品机会”，输出候选商机池给 `hzp-amz-1-2-opportunity-screening`（若该 Skill 尚未建立，则生成可交接包）。它不是产品最终选品、完整产品分析或细分市场决策，不运行完整 2-1/2-2，不输出 GO / CONDITIONAL GO / NO-GO。

机会可以来自搜索需求、消费者痛点、细分市场变化、新品成功、竞争供给弱、产品结构升级、价格带、趋势、供应链能力、团队能力或组合信号。必须把“消费者/场景/需求或问题/现有供给/产品方向/继续验证理由”连起来，而不是只列产品名。

## 输入与数据发现

1. 先读取用户明确的扫描范围、市场、平台和时间窗口。若有 Product Root，优先读取 `[Product Root]/01_产品档案.md`，并在当前 Product Root 的 `05_分析源数据/` 主动发现：
   - `01_产品数据`、`02_细分市场数据`、`03_关键词数据`、`04_用户反馈`、`05_补充资料`。
2. 若是纯市场扫描，可使用用户指定的数据目录，不强制要求 ASIN、Product Code 或 Product Root。搜索范围限定于当前任务目录，禁止无目的扫描整个硬盘。
3. 文件名只是线索。必须读取实际字段、内容、数据日期和口径，判断能支持什么结论；语义不明写 `[字段语义待确认]`。
4. 可读取 Amazon Search Terms/Search Query/ABA/SQP/SCP、H10/Cerebro、Niche、Search Volume、Click Share、Conversion、ASIN、Review、Rating、Price、BSR、Keepa、品牌/卖家/广告/搜索数据及用户提供的市场、供应链和团队资料。截图只能支持可辨识的字段。

## 证据与禁止推断

为每条事实标记 `[FACT]`、`[INFERENCE]`、`[TO-VERIFY]` 或 `[DECISION]`；展示层可同时使用 `[数据支持]`、`[分析推断]`、`[待验证]`、`[证据不足]`、`[数据冲突]`。下游不得把推断或待验证升级为事实。

不得编造销量、搜索量、份额、CVR、评论频率、利润、成本、CPC、ACoS、市场规模、趋势持续性、IP/合规结论；不得把 BSR 当销量、H10 Suggested Bid 当 CPC、Click Share 当销售份额。高销量、高搜索量、低竞争、一条差评、高价格、页面差、工厂能做或新品成功都只能是信号，不能直接等于机会。

保留并按需使用 `[IP风险待验证]`、`[合规风险待验证]`、`[团队能力匹配待验证]`、`[趋势机会｜持续性待验证]`、`[工程改进可能]`、`[商业空间待进一步验证]`、`[推算指标]`。

## 发现方法

覆盖并区分：产品机会、市场机会、页面机会、流量机会和价格机会。检查搜索增长与季节性、Niche 边界、重复评论痛点及消费者重要度、竞品结构和供给缺口、价格带、新品可复制性、趋势、供应链/团队匹配。反向证据必须单列，包含：是否只是销售结果、痛点是否重复且重要、是否依赖品牌、低竞争是否其实低需求、页面问题能否转成产品价值、创新是否只是工程自嗨、团队/IP/合规/成本证据是否缺失。

不要固定候选数量或强行输出 Top 10/20/100；允许零候选。不要用没有证据的综合评分、雷达图或伪精确排名。候选信号等级仅可用：`【强机会信号】`、`【中等机会信号】`、`【弱机会信号】`、`【反向信号】`、`【证据不足】`。

## 候选商机池

为每个候选生成稳定的 `CAND-001` 等 Candidate ID（不可冒充 Product Code），至少包含：

- 商机方向、Marketplace、机会来源标签（如 `【搜索需求增长】`、`【消费者痛点】`、`【细分市场变化】`、`【新品成功】`、`【竞争供给弱】`、`【产品结构升级】`、`【价格带机会】`、`【趋势机会】`、`【供应链能力】`、`【团队能力】`、`【组合信号】`、`【其他明确来源】`）
- 核心消费者、使用场景、JTBD/母需求、现有供给问题、产品解决空间、消费者可感知价值
- 市场证据、竞争信号、价格带（有证据才写）、商业空间初判、供应链/团队匹配、IP/合规早期风险
- 反向证据、最大未知项、下一步验证、信号等级、研究优先级

候选研究状态只能用：`【优先进入1-2】`、`【进入1-2】`、`【保留观察】`、`【暂不进入候选池】`、`【证据不足】`。这些是研究优先级，不是 GO/NO-GO。

## 输出与归档

正式 HTML 章节至少包括：

1. 商机发现结论
2. 本次扫描范围
3. 数据来源与时间窗口
4. 数据语义与限制
5. 商机信号来源
6. 候选商机池
7. 消费者需求/问题信号
8. 市场与竞争信号
9. 产品可开发性
10. 商业空间初判
11. 供应链/团队匹配
12. IP / 合规早期风险
13. 反向证据
14. 机会未知项
15. 机会模式观察
16. 研究优先级
17. 反方检查
18. 总体状态
19. 1-2 输入交接包
20. 数据与证据局限
21. 名词术语解释

总体状态只能用：`【发现高优先级候选商机】`、`【发现可继续初筛的候选商机】`、`【仅发现观察型机会】`、`【当前未发现值得进入1-2的明确机会】`、`【关键数据不足｜暂无法完成可靠商机发现】`。缺普通数据时继续完成可支持的部分；只有身份冲突、市场对象无法确认或关键证据缺失导致无法安全分析时才停止并说明补数要求。

有 Product Root 时报告文件名为：
`[Product Root]/06_SKILL分析报告/1-1_[产品编号]_商机发现_V[版本号]_[YYYYMMDD]_[HHMMSS].html`。
版本号读取当前同产品同 Skill 的最大 V 后递增，历史文件保留。确认 HTML 成功落盘后，只调用 `hzp-amz-0-2-report-index`，原样传递本次已确认的 Product Code、Products Root、Product Root；2-1 自身不生成或维护 `index.html`。索引失败不删除报告，明确报告成功、索引失败及原因。

纯市场扫描没有 Product Code/Product Root 时，不得臆造编号或调用 0-2；保留在当前扫描目录，并标记 `[市场扫描正式归档规则待确认]`。

图表仅在有真实数据时生成；没有足够数据则写 `[数据不足，未生成该图表]`。报告首页显示 Skill、Marketplace、扫描范围、数据日期、总体状态、信号数、候选数、优先数、最强方向、最大反向信号、最大未知项和下一步。

## 1-2 输入交接

交接包只保留影响下一阶段判断的信息，不复制完整报告。包含候选 ID、方向、证据标签、消费者与场景、需求/痛点、供给缺口、关键数据来源、反向证据、未知项、需验证问题、研究优先级和“不得重新假设”的事项。参见 `references/handoff-schema.md`。
