# 5-5 正式 HTML 报告大纲

## LEVEL 1｜老板首页

首页标题固定为：`5-5｜线上页面体检`。

副标题显示：`Product Code + 产品中文名称`、`Var_Code`、`Var_Name`（如有）和 `ASIN`。技术字段可放在“查看详细证据”区域，不抢占视觉中心。

首页按以下顺序展示：

1. **《一句话结论》**：最多 2～3 句，直接说明页面是否有大问题、影响和当前建议。
2. **经营结论**：使用【不用改】、【小改】、【建议重点优化】、【建议重做部分页面】、【暂时无法判断】，下方补一句原因。
3. **《页面体检结果》**：主图、标题、前 3 张副图、五点描述、A+、价格/优惠、评论承接、整体策略。状态只用 🟢 没问题、🟡 值得优化、🔴 需要处理、⚪ 暂时无法判断；每项最多一句解释。
4. **《现在最值得做的3件事》**：最多 3～5 项，每项固定写“哪里有问题、为什么、建议、交给谁”。
5. **《这次不建议动的地方》**：列出保持项及证据理由。
6. **《如果销量不好，问题更可能在哪里？》**：页面内容、图片表达、价格/Offer、广告流量、产品本身分别用经营语言描述，并给出一句当前更可能的方向。
7. **《原来想怎么卖，现在页面有没有做到？》**：老板版策略对照摘要；详细矩阵放 LEVEL 2。
8. **《7张图片，一张一张看》**：逐张写任务、当前表现、建议保持/优化和责任 Skill。
9. **《文案有没有把产品说清楚？》**：标题、Item Highlights、Bullet、Description、A+逐项给出现状、问题、影响、是否要改。
10. **《客户现在能不能顺利买？》**：价格、Coupon、库存、Buy Box、配送、购买按钮；无法确认时明确写暂不下结论。
11. **《跟现在的竞品比，还够不够强？》**：主图、价格、Review、核心卖点、差异化和竞争力判断。
12. **《接下来怎么做》**：按顺序给出动作、责任 Skill 和验证方式。

## LEVEL 2｜专业证据

1. 产品身份与页面审核结论
2. 输入版本追溯
3. 审核范围与审核类型
4. Live Page Snapshot
5. 策略 → 线上执行追踪矩阵
6. Listing Copy Audit
7. Main Image Audit
8. Secondary Image / Video / A+ Audit
9. First-Screen Audit
10. Conversion Persuasion Audit
11. Search & Semantic Audit
12. Offer Audit
13. Review / VOC Audit
14. Competitive Reality Check
15. Root Cause Diagnosis
16. Optimization Priority
17. Final Modification List
18. Skill Routing
19. 反方检查
20. 6-2输入交接包（仅条件满足）
21. 数据与证据局限
22. 名词术语解释

LEVEL 2 可以保留英文技术字段、证据标签、状态码和根因枚举，但必须附中文解释；不得删除专业证据。

## 表达和样式约束

- 中文优先，使用 UTF-8；Amazon 常用术语（ASIN、SKU、Title、Bullet、A+、Coupon、Buy Box 等）可保留。
- 首页不显示 `LIVE_PAGE_ANOMALY`、`STRATEGY_MISALIGNMENT`、`OFFER_NOT_VERIFIED`、`ROOT_CAUSE`、`PASS/PARTIAL/GAP` 等机器状态码作为主标题；这些仅放 LEVEL 2。
- 视觉采用清晰的卡片、留白、圆角和对比色；不使用综合评分、雷达图、AI 信心分或没有业务意义的仪表盘。
- 正式报告仍须保留既有身份解析、证据规则、根因逻辑、最新版输入追溯、6-2 交接条件和输出命名规则。

## 主状态

主状态继续使用：HEALTHY、MINOR_OPTIMIZATION、MAJOR_OPTIMIZATION、STRATEGY_MISALIGNMENT、LIVE_PAGE_ANOMALY、INSUFFICIENT_EVIDENCE；在 LEVEL 1 同时翻译为老板可读的经营结论。
