# HZP Amazon 7-1｜补货预测

## 定位与边界

7-1 负责回答：从今天开始库存还能撑多久、下一批何时真正可售、何时下单、补多少，以及断货和积压风险。6-3 负责发现库存风险，7-2 负责持续库存风险管理；7-1 不替代 7-2，不做其他 Skill 的完整分析。

- 使用真实库存、销售、在途、供应商、物流、推广和促销证据。
- 不修改 `01_产品档案.md`、原始库存/供应链数据、历史 HTML 或 `index.html`。
- 运行连续完成已定义步骤，不要求用户逐阶段确认。

## 输入与身份

使用本次确认的 Products Root、Product Root 和 Product Code。先读取：

1. `[Product Root]/01_产品档案.md`；身份缺失或冲突时停止，禁止根据 ASIN、文件名或经验猜身份。

4. 按需辅助回查最新有效 6-2、6-1、5-4、2-2、2-1，确认推广放量、促销影响、销量变化、页面状态和市场需求；不得重新完整执行这些 Skill。

## 最新版本与追溯

按 `Product Code + Skill 编号` 选择版本化正式报告：最大 `V` 优先，同 `V` 按文件名 `YYYYMMDD_HHMMSS` 最新。排除 `index`、失败、invalid、incomplete、deprecated、draft、preview、temp、test 和非正式输出；不得使用 filesystem 顺序、modified time、created time、跨产品文件或静默旧版回退。无法确认有效性时标记 `【上游报告有效性无法确认】`。

正式 HTML 必须生成《输入版本追溯》，记录实际读取的 Skill 编号、中文名称、文件名、版本、时间戳、输入类型和用途。6-3 为【核心输入】；6-2/6-1 等按需为【辅助回查】；历史版本为【历史版本对照】。

## 核心计算原则

补货不是“日销量×固定天数”。在证据允许时按：

`未来需求 − 现有可及时使用库存 − 可在需求发生前及时到货库存 + 安全库存 = 理论补货量`

`Lead Time 期间需求 + Safety Stock = Reorder Point`

必须区分 Available、Reserved、Inbound、在途、已下单未发、已下单未完成生产、计划补货和其他库存。计划下单或供应商口头说有货不等于可用库存；Reserved 不得自动全部加入 Available；Inbound 只有在预计变为 Sellable/Available 的时间早于库存耗尽点时才可作为及时到货库存。

### 库存与时间

《库存到货时间轴》逐批记录数量、状态、所在位置/阶段、下单、生产完成、出货、到港/到仓、Amazon 可售时间、证据来源、风险及是否赶得上库存耗尽点。库存覆盖至少区分 Available 覆盖、可及时到货库存覆盖和总名义库存覆盖，并说明分子库存和销售速度分母。

### 销售速度与情景

销售速度状态只能使用：`【稳定销量】`、`【增长中】`、`【下降中】`、`【促销驱动】`、`【广告驱动】`、`【异常期】`、`【数据不足】`。结合近 7/14/30 天和更长历史（仅在真实覆盖时）、当前阶段、广告、促销、价格、页面、断货、Buy Box 和自然排名；不机械取平均。促销峰值、断货期、页面受限或广告异常期不能直接外推为正常需求。

不确定性较高时使用保守/基准/增长情景中的必要子集。每个情景必须写日/周需求假设、依据、广告/促销、Organic 趋势、季节影响、风险和适用条件，并明确本次正式建议采用哪个情景。预测应给区间或触发重算条件，不能声称单值绝对准确。

### Lead Time 与安全库存

Lead Time 尽量拆为生产前准备、生产、验货/出货、国内运输、国际运输、清关、目的地运输、Amazon 预约/入仓、Receiving 和缓冲。每段写时间、来源、确认状态和历史波动；不完整时标记 `[Lead Time待确认]`。安全库存结合销量/Lead Time 波动、供应商与物流稳定性、断货成本、利润、补货频率、现金压力、季节和促销；禁止所有产品固定 30 天，证据不足标记 `[安全库存待确认]`。

### 计算与约束

《补货计算表》必须显示当前日期、库存处理方式、销售速度、情景、Lead Time、Safety Stock、Reorder Point、下单/可售日期、到货前需求、到货时剩余、理论补货量、MOQ/整箱约束、调整后实际建议量、风险和证据状态。MOQ、Carton Qty、Pallet Qty 只有真实资料存在时才应用，并明确“理论需求 vs 约束后数量”，不得悄悄改数。

如果库存耗尽早于下一批可售，标记断货风险并交接降低推广、暂停大促、调整 Coupon、加急物流或优先核心 SKU 的选项，但不越权直接改广告。如果需求走弱、覆盖过长或现金压力大，识别积压风险并允许暂缓补货。广告放量计划、可能做 Deal 或季节常识只能进入情景/不确定性，不得当作销量事实。

## 最终状态与边界

最终补货状态只能使用：

- `【需要补货｜按建议数量执行】`
- `【接近补货点｜准备下单】`
- `【暂不补货｜库存充足】`
- `【高断货风险｜优先处理补货】`
- `【高积压风险｜暂缓补货】`
- `【关键数据不足｜暂无法形成可靠补货预测】`

建议必须是“数字 + 使用条件 + 风险”。缺少真实库存、当前销售速度、Lead Time 或 Inbound 可售时间而无法可靠计算时，必须使用关键数据不足状态，不硬算数量。7-1 可以明确暂不补货。
